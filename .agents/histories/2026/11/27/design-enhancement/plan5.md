# 4단계 통합 검증 계획

> 4단게 계획 말해줘

## 답변

4단계는 통합 검증 단계. 아래 7개 순서로 진행하고, 최종 보고 후 멈춘다.

## 진행 순서

### 1. 유지 항목 대조

- `sloplint --kept`로 25개 화면을 0단계 기록(링크 61, 입력 필드 20, 핸들러 88, 제목, 숫자)과 비교.
- 빠진 게 있으면 결과가 이렇게 나옴.
  - `FAIL kept`: 링크·폼·필드·핸들러 같은 동작이 사라짐
  - `WARN kept`: 제목·숫자·id 같은 내용이 사라짐
- 처리 방식.
  - 의도해서 지운 것(경로 라벨, 중복 제목 글자 등): hallmark 규칙대로 `globals.css` 기록 줄에 `dropped … · 이유`로 남김.
  - 의도하지 않게 빠진 것: 복구. 복구 대상이 화면 코드면 무엇을 고칠지 먼저 보고.
- 이 실행에서 before/after 비교 파일(`.hallmark/compare.html`)도 같이 만들어짐.

### 2. 빌드

- `npm run build`(`next build`)가 성공하는지 확인. 지금까지는 타입 체크, 테스트, dev 서버만 확인했고 프로덕션 빌드는 아직 안 돌려봄.

### 3. 라이트 테마 확인

- hallmark 브라우저 검사는 기본 모드(다크)만 봄. 그래서 `data-theme="light"`로 바꾼 상태를 따로 확인.
  - 주요 화면 스크린샷
  - 글자·테두리 대비는 숫자로 측정
- 라이트 테마를 켜는 버튼은 없지만 유지하기로 했으니 깨지면 안 됨.

### 4. 작업자들이 요청한 브라우저 확인

- 320~414px 좁은 화면: 상단 경로 링크, 줄바꿈, 홈 서비스 바로가기 가로 스크롤
- 키보드 포커스: 공지·블로그·피드 모달, 가격 차트 지점
- 기타: 방송 기록 팝오버 위치, 앨범 캐러셀의 모션 줄이기 설정 대응
- 문제가 보이면 고칠 범위와 방법을 먼저 보고.

### 5. hallmark 기록 마무리

- `globals.css` 맨 위 hallmark 기록 줄을 채움.
  - 지금은 `pre-emit critique: P_ H_ E_ S_ R_ V_ · weakest: _`처럼 빈칸으로 남아 있음. hallmark 필수 규칙(Floor 15).
  - 예외 항목을 사유와 함께 기록: 네이버 대비, 행 버튼 높이, `/feed` 제목 간격, 로고 굵기.
- `.hallmark/log.json`에 이번 작업 기록을 남김(`theme.mjs log`).

### 6. 마무리 리뷰

- hallmark는 마지막에 작업에 참여하지 않은 눈으로 before/after 스크린샷을 비교하는 리뷰를 요구함. "예전 화면이 더 나았던 점이 있는가"를 묻는 리뷰.
- 방식은 둘 중 하나.
  - **가. paseo로 리뷰어 1명 띄우기 (추천)**: 작업에 참여하지 않은 에이전트가 스크린샷만 보고 판단. 3단계처럼 띄움.
  - **나. Claude가 직접**: 빠르지만, 직접 만든 걸 직접 보는 거라 객관성이 떨어짐.
- 리뷰에서 나온 지적 가운데 명백한 결함(어긋남, 깨진 글자 등)은 고침. 구성 변경이 필요한 건 목록으로 보고.

### 7. 최종 보고

hallmark 형식에 맞춰 정리.

| 항목 | 내용 |
|---|---|
| Before/After | 점검 수치 (36/34/8 → 최종) |
| Kept | 유지된 링크·필드·핸들러·제목 수 |
| Changed | 바뀐 것 (시스템, 화면 구성, 셸) |
| Dropped | 지운 것 목록과 이유 |
| Yours | 바꾼 문구, 수정한 테스트 목록 |
| 예외 | 네이버 대비 등 |
| 주인에게 넘길 것 | 실데이터 연동, 로딩·오류 상태, 저장 API, 보류한 공용 요청 3건 |
| Compare | `.hallmark/compare.html` 경로 |

보고 후 멈춤.
