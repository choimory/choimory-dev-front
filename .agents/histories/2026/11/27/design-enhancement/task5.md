# 4단계 통합 검증 진행

## 1. 유지 항목 대조

- `sloplint --kept`로 25개 화면을 0단계 기록과 비교.
- 결과: 모두 유지.

## 2. 빌드

- `npm run build` 성공. 20개 라우트 모두 생성.

## 3. 라이트 테마 확인

- hallmark 브라우저 검사는 다크(기본)만 보므로, 스크립트로 `data-theme="light"`를 적용해 25개 화면의 글자 대비와 입력칸 테두리 대비를 측정.
- 다크·라이트 모두 통과. 걸린 것은 네이버 버튼(2.25:1) 하나뿐이고, 정해둔 브랜드 예외.
- 라이트 모드 스크린샷에 Next 개발 오버레이 "1 Issue"가 보였는데, 원인은 테스트 스크립트가 React가 화면을 붙이기 전에 테마를 바꿔서 생긴 hydration 불일치. 페이지가 다 뜬 뒤 바꾸면 콘솔 오류가 없어 앱 문제가 아님을 확인.

## 4. 작업자 요청 브라우저 확인

| 항목 | 결과 |
|---|---|
| 320·375·414px × 25개 화면 | 가로로 넘치는 화면 없음, 상단 경로 한 줄 유지, 콘솔 오류 없음 |
| 홈 서비스 바로가기 | 375px에서 다음 버튼을 누르면 가로로 240px 이동 |
| 모달 3개(공지, 글쓰기, 피드 등록) | 375px 화면 안에 다 들어오고, 길면 내부 스크롤 |

- 블로그 `/blog`의 "글쓰기" 버튼은 원래부터 핸들러가 없음(글쓰기 모달은 `/blog/me`의 "무슨 생각을 공유할까요?"에서 열림). 유지 항목 대조의 핸들러 88/88과 일치.

- **예외 처리(waive)**: 39b(행 전체를 누르는 버튼 높이), 71(`/feed` 비회원 제목 간격).

- `.hallmark/log.json`에 이번 작업 기록 추가(`theme.mjs log`).
- 기록 줄을 채운 뒤에도 정적 검사는 0건.

# 마무리 리뷰 1 (Claude)

> 가 방식으로 진행

## 답변

paseo로 작업에 참여하지 않은 Claude 리뷰어를 띄워 마무리 리뷰를 맡김. 판정은 **fix**.

## 리뷰어 실행

- 모델 `claude/claude-opus-5-5`, 추론 강도 high, 읽기 전용(plan) 모드.
- hallmark 규칙대로 리뷰 지침 파일(`review-finish.md`)은 리뷰어만 읽음. 전달한 자료: before/after 스크린샷, `compare.html`, 컴포넌트 소스, `design.md`, 토큰, 기록 줄, Cobalt 테마 파일과 그림, `gates.md` § 4.
- 사용자가 정한 예외(로고 고정, 네이버 버튼, 경로 라벨 제거, 한국어 문구 유지)는 다시 따지지 않도록 전달.
- 리뷰어가 읽기 전용 모드를 끝내면서 "구현(Implement)" 권한을 요청해 거절함. 수정은 정리해서 승인받은 뒤 진행. 거절하면서 작업을 멈춰 상태가 "errored"로 표시되지만, 리뷰 결과는 그 전에 받음.

## Claude 리뷰 결과

판정 **fix**. 지적 7가지(중요한 순서).

1. **블로그 빈 이미지 박스 (Gate 81)**: 게시글 상세·목록·인기 화면의 이미지 자리가 빈 박스라 이미지가 깨진 것처럼 보임. 상세 화면에서는 화면에서 가장 큰 요소.
2. **화면당 주요 버튼이 하나가 아님**: 상단바 로그인/로그아웃이 모든 화면에서 코발트 주요 버튼. 비회원은 한 화면에서 파란 버튼 둘, 회원은 "로그아웃"이 유일한 주요 버튼.
3. **블로그 인기 순위 상태 표시**: `↑ 12`, `NEW`, `↓ 2`에 배경 칩. `design.md`의 "상태는 글자로, 채운 칩 금지" 위반.
4. **회원 홈 밀도**: 준비 중 서비스 4개가 각각 큰 패널로 하단의 약 45%를 차지.
5. **대상 상세 반복**: 섹션 7개가 같은 패널로 쌓이고, 방송 기록 히트맵은 패널 왼쪽 45%만 씀.
6. **375px 숫자 줄바꿈**: 대상 상세의 `이벤트 12건`이 두 줄로 꺾임.
7. **필요 없는 화살표**: 홈 서비스 목록이 1440px에서 다 들어가는데도 좌우 화살표가 보임.

기타 의견.

- Cobalt는 원래 밝은 종이 테마인데 여기선 다크가 기본. `/me` 설정 화면 문구는 라이트·다크·시스템 선택을 약속하는데 실제 전환 기능은 없음.
- before가 더 나았던 점: 블로그 이미지 자리가 그라디언트로 채워져 그림으로 읽혔음(규칙 위반이었지만). 그 외에 더 어려워진 곳은 없음.
- 지켜야 할 것: 구분선 행 위의 관찰 목록과 정렬된 숫자, 화면당 하나의 코발트 버튼, 고정된 로고.

**건너뛰기**: "실시간 순위" 제목은 한국어 문구 유지 결정에 따라 그대로 둠.

## 결정 필요: 블로그 빈 이미지

게시글 데이터에는 "이미지 있음" 표시(`hasMedia`)만 있고 실제 이미지 주소가 없음. 테스트도 "이미지가 있는 글은 이미지 자리를 보여준다"를 확인함.

- **가. 자리 표시를 분명하게 (추천)**: 공용 `Icon`에 이미지 아이콘을 추가하고, 빈 박스 대신 아이콘이 있는 자리 표시로 바꿈. 목록에서는 크기도 줄여 화면을 덜 차지하게 함.
- **나. 임시 사진 넣기**: hallmark 사진 라이브러리의 임시 사진을 넣고 나중에 실제 이미지로 교체. 실제처럼 보이지만 외부 사진과 출처 표기가 필요.
- **다. 숨기기**: 이미지 자리를 아예 그리지 않음. 데이터의 "이미지 있음" 의미와 테스트를 같이 바꿔야 함.
