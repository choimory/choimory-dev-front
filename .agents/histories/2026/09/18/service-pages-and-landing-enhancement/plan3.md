# 개요

- 플랫폼 비로그인 랜딩에서 소개문구에 blog, feed 같은 영어를 한글로 변경
- 플랫폼 로그인 메인에서는 서비스를 카드별로 구성해서, 서비스별 내 활동 기록들을 표시
- 상단 검색버튼: 통합검색, 서비스별 검색을 지원 (누르면 화면 백그라운드로 흐려지면서 화면 중앙에 검색창이 뜨고, 검색창은 검색바를 하나 놓고 검색바 왼쪽에 selectbox로 서비스를 선택, 검색바 우측엔 검색버튼)
- 상단 알림버튼: 모든 서비스의 알림 (누르면 모든 알림이 조그만 창으로 알림버튼 위에 뜨고, 창 내용은 위에 탭으로 모든 알림/서비스별 알림 있고 그 밑으로 알림 내역들.)
- 플랫폼 툴바: 홈, 공지사항, 서비스, 내 정보
- 블로그 툴바: 홈, 인기(트로피 아이콘), 팔로잉(팔로우한 사람들의 활동만 나오는 피드인데 네이밍을 못정하겠음), 내 블로그
- 피드 툴바: 홈, 인기, 추적(망원경 아이콘), 내 피드

# 추가사항 분석

253번줄 추가사항 기준으로 보면, 이번 추가사항은 단순 문구 수정이 아니라 상단 전역 액션 UX, 서비스별 네비게이션 정책, 플랫폼 회원 홈 구조를 다시 잡는 작업이다.

## 범위 분리

즉시 반영 가능한 것:

- 플랫폼 비로그인 랜딩에서 `blog`, `feed` 같은 영어를 한글 `블로그`, `피드`로 변경
- 플랫폼, 블로그, 피드 하단 툴바 항목을 새 정책으로 변경
- 필요한 아이콘 추가
    - 공지사항
    - 인기용 트로피
    - 추적용 망원경
    - 내 블로그/내 피드용 사용자 또는 북마크 계열 아이콘 재사용 가능

구조 작업이 필요한 것:

- 상단 검색 버튼 클릭 시 중앙 검색 모달
- 상단 알림 버튼 클릭 시 알림 팝오버
- `AppTopBar`는 현재 단순 버튼만 렌더링하므로 client component 전환 또는 내부 client subcomponent가 필요함
- 검색/알림 UI는 모든 서비스에서 공통으로 쓰일 것이므로 `shared/ui` 쪽 설계가 적합함

별도 화면 설계가 필요한 것:

- 플랫폼 로그인 메인에서 서비스별 내 활동 기록 카드 구성
- 이 작업은 `MemberServiceFeedSection`을 확장하는 작업
- 서비스별 활동 카드 구조를 어떻게 잡을지 먼저 정해야 함

## 하단 툴바 정책 분석

새 정책:

플랫폼:

- 홈
- 공지사항
- 서비스
- 내 정보

블로그:

- 홈
- 인기
- 팔로잉
- 내 블로그

피드:

- 홈
- 인기
- 추적
- 내 피드

좋은 점:

- 각 서비스마다 4개 항목으로 유지되어 모바일 하단바에 적당하다.
- 첫 번째 `홈`을 각 서비스 홈으로 해석할 수 있다.
- 마지막 항목을 내 공간 또는 내 서비스 홈으로 둬서 개인 영역 진입이 명확하다.

주의할 점:

- 플랫폼의 `홈`은 `/`
- 블로그의 `홈`은 `/blog`
- 피드의 `홈`은 `/feed`
- 플랫폼으로 돌아가는 이동은 상단 로고 `choimory.dev`가 담당한다.
- 따라서 하단 툴바의 `홈`은 현재 영역의 홈으로 통일하는 것이 좋다.

## 네이밍 제안

블로그의 `팔로잉`은 그대로 사용해도 좋다.

대안:

- 팔로잉
- 구독
- 관계
- 소식
- 내 구독

인스타그램형 블로그/SNS라면 `팔로잉`이 가장 직관적이다.

피드의 `추적`도 적절하다.

망원경 아이콘까지 함께 사용하면 의미가 더 잘 살아난다.

## 상단 검색 UX 분석

요구사항:

- 상단 검색 버튼 클릭
- 화면 배경 흐림
- 중앙 검색창 표시
- 왼쪽 selectbox로 검색 대상 선택
- 오른쪽 검색 버튼

추천 구조:

- `AppTopBar` 전체를 client component로 바꾸는 방법이 가장 단순하다.
- 하지만 더 깔끔하게 하려면 검색/알림 버튼 영역만 클라이언트 컴포넌트로 분리한다.
- 추천은 `TopBarActions` 분리다.
    - 상단바 전체를 client로 만들지 않아도 된다.
    - 검색 모달/알림 팝오버 상태를 액션 영역 안에서 관리할 수 있다.

예상 구조:

```text
src/shared/ui/TopBarActions.tsx
src/shared/ui/SearchOverlay.tsx
src/shared/ui/NotificationPopover.tsx
```

초기에는 실제 검색/알림 기능 없이 UI만 구현한다.

검색 대상:

- 전체
- 블로그
- 피드

알림 샘플:

- 새 댓글
- 방송 시작
- 가격 하락

## 상단 알림 UX 분석

요구사항:

- 모든 서비스 알림
- 클릭 시 알림 버튼 위에 작은 창
- 탭: 모든 알림 / 서비스별 알림
- 알림 내역 표시

주의할 점:

- 모바일 320px에서는 버튼 위 작은 창이 화면 밖으로 나갈 수 있다.
- 따라서 데스크톱/태블릿에서는 버튼 근처 팝오버, 모바일에서는 화면 중앙 또는 하단 sheet에 가까운 형태가 안정적이다.
- 초기 구현은 `absolute right-0 top-12 w-[min(calc(100vw-2rem),320px)]` 형태로 잡으면 안정적이다.

## 플랫폼 로그인 메인 카드화

현재 회원용 플랫폼 홈:

- 오늘 요약 3개
- 최근 활동 리스트

요구사항:

- 서비스를 카드별로 구성
- 서비스별 내 활동 기록 표시

추천 구조:

- `MemberServiceFeedSection`을 확장한다.
- 서비스 카드 예:
    - 블로그: 새 댓글, 인기 글, 팔로잉 소식
    - 피드: 새 알림, 추적 중 항목, 가격 하락
    - 메모/일정/가계부: 준비 중 카드 또는 비활성 카드

다만 이 작업은 상단 검색/알림보다 범위가 커질 수 있으므로 단계를 나누는 것이 좋다.

## 추가사항 추천 구현 순서

1. 문구와 하단 툴바 정책 먼저 반영
    - 플랫폼 비로그인 랜딩 영어를 한글로 변경
    - 플랫폼 툴바: 홈 / 공지사항 / 서비스 / 내 정보
    - 블로그 툴바: 홈 / 인기 / 팔로잉 / 내 블로그
    - 피드 툴바: 홈 / 인기 / 추적 / 내 피드
    - 필요한 아이콘 추가: `trophy`, `telescope`, `megaphone`
2. 상단 검색/알림 UI 추가
    - `TopBarActions` 클라이언트 컴포넌트 추가
    - 검색 오버레이 추가
    - 알림 팝오버 추가
    - 실제 기능 없이 UI 상태만 구현
3. 플랫폼 회원 메인 카드화
    - `MemberServiceFeedSection` 확장
    - 서비스별 활동 카드 추가
    - blog/feed active, 미래 서비스 planned 구분 반영

# 추가사항

- 상단 검색버튼 눌렀을때 화면 블러처리가 상단바에만 먹는데, 전체 다먹어야함
- 상단 검색버튼 눌렀을때 검색바가 화면 정중앙에 와야하는데 상단에 있음
- 상단 검색바 눌렀을때 이런저런 창이나 텍스트 말고 길쭉한 검색바 하나만 블러위에 올라온 느낌으로 심플하게 있으면 좋겠음
- 내 블로그, 내 피드의 아이콘인 북마크 아이콘이 맘에 안듬 다른거 없나
