# 개요

- 플랫폼 비로그인 랜딩에서 소개문구에 blog, feed 같은 영어를 한글로 변경
- 플랫폼 로그인 메인에서는 서비스를 카드별로 구성해서, 서비스별 내 활동 기록들을 표시
- 상단 검색버튼: 통합검색, 서비스별 검색을 지원 (누르면 화면 백그라운드로 흐려지면서 화면 중앙에 검색창이 뜨고, 검색창은 검색바를 하나 놓고 검색바 왼쪽에 selectbox로 서비스를 선택, 검색바 우측엔 검색버튼)
- 상단 알림버튼: 모든 서비스의 알림 (누르면 모든 알림이 조그만 창으로 알림버튼 위에 뜨고, 창 내용은 위에 탭으로 모든 알림/서비스별 알림 있고 그 밑으로 알림 내역들.)
- 플랫폼 툴바: 홈, 공지사항, 서비스, 내 정보
- 블로그 툴바: 홈, 인기(트로피 아이콘), 팔로잉(팔로우한 사람들의 활동만 나오는 피드인데 네이밍을 못정하겠음), 내 블로그
- 피드 툴바: 홈, 인기, 추적(망원경 아이콘), 내 피드

---

# 추가사항

- 상단 검색버튼 눌렀을때 화면 블러처리가 상단바에만 먹는데, 전체 다먹어야함
- 상단 검색버튼 눌렀을때 검색바가 화면 정중앙에 와야하는데 상단에 있음
- 상단 검색바 눌렀을때 이런저런 창이나 텍스트 말고 길쭉한 검색바 하나만 블러위에 올라온 느낌으로 심플하게 있으면 좋겠음
- 내 블로그, 내 피드의 아이콘인 북마크 아이콘이 맘에 안듬 다른거 없나

# 추가사항 분석

253번줄 추가사항 기준으로 보면, 이번 추가사항은 단순 문구 수정이 아니라 상단 전역 액션 UX, 서비스별 네비게이션 정책, 플랫폼 회원 홈 구조를 다시 잡는 작업이다.

## 범위 분리

즉시 반영 가능한 것:

- 플랫폼 비로그인 랜딩에서 `blog`, `feed` 같은 영어를 한글 `블로그`, `피드`로 변경
- 플랫폼, 블로그, 피드 하단 툴바 항목을 새 정책으로 변경
- 필요한 아이콘 추가
    - 공지사항
    - 인기용 트로피
    - 추적용 망원경
    - 내 블로그/내 피드용 사용자 또는 북마크 계열 아이콘 재사용 가능

구조 작업이 필요한 것:

- 상단 검색 버튼 클릭 시 중앙 검색 모달
- 상단 알림 버튼 클릭 시 알림 팝오버
- `AppTopBar`는 현재 단순 버튼만 렌더링하므로 client component 전환 또는 내부 client subcomponent가 필요함
- 검색/알림 UI는 모든 서비스에서 공통으로 쓰일 것이므로 `shared/ui` 쪽 설계가 적합함

별도 화면 설계가 필요한 것:

- 플랫폼 로그인 메인에서 서비스별 내 활동 기록 카드 구성
- 이 작업은 `MemberServiceFeedSection`을 확장하는 작업
- 서비스별 활동 카드 구조를 어떻게 잡을지 먼저 정해야 함

## 하단 툴바 정책 분석

새 정책:

플랫폼:

- 홈
- 공지사항
- 서비스
- 내 정보

블로그:

- 홈
- 인기
- 팔로잉
- 내 블로그

피드:

- 홈
- 인기
- 추적
- 내 피드

좋은 점:

- 각 서비스마다 4개 항목으로 유지되어 모바일 하단바에 적당하다.
- 첫 번째 `홈`을 각 서비스 홈으로 해석할 수 있다.
- 마지막 항목을 내 공간 또는 내 서비스 홈으로 둬서 개인 영역 진입이 명확하다.

주의할 점:

- 플랫폼의 `홈`은 `/`
- 블로그의 `홈`은 `/blog`
- 피드의 `홈`은 `/feed`
- 플랫폼으로 돌아가는 이동은 상단 로고 `choimory.dev`가 담당한다.
- 따라서 하단 툴바의 `홈`은 현재 영역의 홈으로 통일하는 것이 좋다.

## 네이밍 제안

블로그의 `팔로잉`은 그대로 사용해도 좋다.

대안:

- 팔로잉
- 구독
- 관계
- 소식
- 내 구독

인스타그램형 블로그/SNS라면 `팔로잉`이 가장 직관적이다.

피드의 `추적`도 적절하다.

망원경 아이콘까지 함께 사용하면 의미가 더 잘 살아난다.

## 상단 검색 UX 분석

요구사항:

- 상단 검색 버튼 클릭
- 화면 배경 흐림
- 중앙 검색창 표시
- 왼쪽 selectbox로 검색 대상 선택
- 오른쪽 검색 버튼

추천 구조:

- `AppTopBar` 전체를 client component로 바꾸는 방법이 가장 단순하다.
- 하지만 더 깔끔하게 하려면 검색/알림 버튼 영역만 클라이언트 컴포넌트로 분리한다.
- 추천은 `TopBarActions` 분리다.
    - 상단바 전체를 client로 만들지 않아도 된다.
    - 검색 모달/알림 팝오버 상태를 액션 영역 안에서 관리할 수 있다.

예상 구조:

```text
src/shared/ui/TopBarActions.tsx
src/shared/ui/SearchOverlay.tsx
src/shared/ui/NotificationPopover.tsx
```

초기에는 실제 검색/알림 기능 없이 UI만 구현한다.

검색 대상:

- 전체
- 블로그
- 피드

알림 샘플:

- 새 댓글
- 방송 시작
- 가격 하락

## 상단 알림 UX 분석

요구사항:

- 모든 서비스 알림
- 클릭 시 알림 버튼 위에 작은 창
- 탭: 모든 알림 / 서비스별 알림
- 알림 내역 표시

주의할 점:

- 모바일 320px에서는 버튼 위 작은 창이 화면 밖으로 나갈 수 있다.
- 따라서 데스크톱/태블릿에서는 버튼 근처 팝오버, 모바일에서는 화면 중앙 또는 하단 sheet에 가까운 형태가 안정적이다.
- 초기 구현은 `absolute right-0 top-12 w-[min(calc(100vw-2rem),320px)]` 형태로 잡으면 안정적이다.

# 검색 오버레이와 개인 서비스 아이콘 재분석

## 현재 문제

검색 오버레이 블러가 전체 화면이 아니라 상단바 근처에만 걸리는 느낌이 있다.

- 현재 `TopBarActions`가 `AppTopBar` 안에 있고, 검색 오버레이도 그 내부에서 렌더링된다.
- `fixed inset-0`를 쓰고 있더라도, 부모가 상단바 안이라 stacking context나 header 구조 때문에 상단바 안에서 뜨는 느낌이 날 수 있다.
- 실제 체감상 전체 화면을 덮는 모달이 아니라 상단에 붙은 패널처럼 보이는 상태다.

검색창 위치가 화면 정중앙이 아니라 상단에 가깝다.

- 현재 overlay가 `grid place-items-center`라도, header 내부 렌더링/레이어 영향 때문에 화면 전체 기준 중앙으로 느껴지지 않을 수 있다.
- 또한 검색 UI가 `section` 카드 형태라 검색창 하나보다 모달 창처럼 보인다.

검색 UI가 과하다.

- 제목 `통합 검색`
- 닫기 버튼
- 카드 패널
- 내부 여백

이 구조가 원하는 블러 위에 긴 검색바 하나 느낌과 다르다.

`내 블로그`, `내 피드` 아이콘으로 bookmark가 어색하다.

- 북마크는 저장 의미가 강하다.
- 내 블로그/내 피드는 내 공간, 내 페이지, 개인 홈 의미라 더 맞는 아이콘이 필요하다.

## 검색 오버레이 추천 방향

요구사항은 전체 블러, 화면 정중앙, 길쭉한 검색바 하나다.

추천 구조:

- overlay
  - `fixed inset-0 z-50`
  - `bg-black/60 backdrop-blur-sm`
  - 전체 화면 클릭 시 닫기 가능
- 검색바 wrapper
  - `absolute left-1/2 top-1/2`
  - `-translate-x-1/2 -translate-y-1/2`
  - `w-[min(calc(100vw-2rem),720px)]`
- 검색바
  - 한 줄 구성
  - 왼쪽 select
  - 가운데 input
  - 오른쪽 검색 버튼
  - 닫기 버튼은 별도 텍스트 없이 overlay 클릭으로 닫거나 우측 작은 `×` 아이콘 정도만 둔다.
- 제목과 설명은 제거한다.

예상 UI:

```text
[ 전체 ▼ ][ 검색어 입력 __________________ ][ 검색 ]
```

모바일에서는 3칸이 너무 좁을 수 있으므로 다음을 지킨다.

- `grid-cols-[92px_minmax(0,1fr)_auto]`
- 버튼 padding 줄이기
- input `min-width: 0` 필수

## 구현 방법

`TopBarActions.tsx`의 검색 오버레이 부분만 수정하면 된다.

현재 구조:

- `section` 카드
- 제목
- 닫기 버튼
- form이 카드 안에 있음

변경 구조:

- overlay 안에 바로 form 배치
- form이 화면 중앙에 오도록 `fixed inset-0` 내부에서 absolute centering
- 카드 배경은 form 자체에만 적용
- 제목 제거

## 알림 팝오버는 이번 범위에서 유지

이번 피드백은 검색 오버레이에 집중되어 있다.

알림은 현재 요구와 크게 충돌하지 않는다.

- 버튼 위 팝오버
- 탭/목록 구조

따라서 이번 범위에서는 유지한다.

## 내 블로그와 내 피드 아이콘 추천

현재 `bookmark`가 별로인 이유는 타당하다.

# 검색바 브라우저 화면 중앙 정렬 재분석

> 검색바가 상단바 중앙에 뜨는데 내가 원하는건 브라우저 화면 정중앙에 오는거야

## 답변

현재 검색 오버레이가 `TopBarActions` 컴포넌트 내부에서 렌더링되고 있어서, CSS에서 `fixed inset-0`와 `top-1/2`를 사용해도 상단바 DOM 구조나 stacking context 영향으로 상단바 중앙에 뜨는 것처럼 보일 수 있다.

원하는 동작은 상단바가 아니라 브라우저 viewport 전체를 기준으로 검색바가 정중앙에 뜨는 것이다.

## 구현 방향

- 검색 오버레이 JSX를 `TopBarActions` 내부 DOM 흐름에 그대로 두지 않는다.
- React `createPortal`을 사용해서 검색 오버레이를 `document.body`에 렌더링한다.
- 오버레이는 `fixed inset-0 z-50`로 브라우저 화면 전체를 덮는다.
- 검색바는 `fixed left-1/2 top-1/2 -translate-x-1/2 -translate-y-1/2`로 viewport 기준 중앙에 둔다.
- 배경 클릭 시 닫히는 동작은 유지한다.
- 검색 실제 동작은 이번 범위에서 제외한다.

## 결론

검색바 위치 문제는 CSS 값만 조정하는 것보다 portal 구조로 분리하는 것이 맞다.

이번 수정은 `TopBarActions.tsx`에서 검색 오버레이를 `document.body`로 portal 렌더링하도록 바꾸는 방식으로 진행한다.

# 추가사항2 분석

## 답변

`추가사항2`는 검색 오버레이의 시각적 완성도와 알림 탭 구조를 다시 잡는 내용이다.

검색 오버레이는 현재 portal로 브라우저 viewport 기준 중앙에는 왔지만, 실제 사용감에서는 정확한 중앙보다 살짝 위가 더 자연스럽다. 검색 UI는 사용자가 입력하는 동안 키보드, 결과 영역, 시선 흐름이 아래쪽으로 이어질 가능성이 크기 때문에 검색바를 화면 정중앙보다 위쪽에 두는 편이 안정적이다.

추천 위치는 `top-1/2` 대신 `top-[42%]` 정도다.

검색바 위 로고 추가도 좋은 방향이다. 현재는 전체 화면 블러 위에 검색바 하나만 떠 있어서 기능적으로는 깔끔하지만 화면이 비어 보일 수 있다. 로고를 검색바 위 중앙에 두면 사용자가 현재 어느 서비스/플랫폼에서 검색하는지 자연스럽게 인지할 수 있고, 플랫폼 브랜딩도 유지된다.

다만 로고가 너무 크면 검색 모달처럼 무거워 보일 수 있으므로 작은 워드마크 느낌으로 두는 것이 좋다.

## 검색 오버레이 구현 방향

- overlay는 계속 `document.body` portal 렌더링을 유지한다.
- overlay 안에 중앙 column wrapper를 둔다.
- wrapper 위치는 `fixed left-1/2 top-[42%] -translate-x-1/2 -translate-y-1/2`로 잡는다.
- wrapper 안에 로고와 검색바를 세로 배치한다.
- 로고는 검색바 위 가운데 정렬로 둔다.
- 검색바 자체의 select/input/button 구조는 유지한다.

## 알림 탭 구조 분석

이전 구현의 `전체 / 서비스별` 탭은 요구사항을 잘못 해석한 부분이다.

요구한 의미는 `서비스별`이라는 텍스트 탭 하나가 아니라, 실제 서비스들을 탭으로 나눠 표현하는 구조에 가깝다.

추천 구조:

- 전체
- 블로그
- 피드
- 이후 메모, 일정, 가계부

`전체` 탭에서는 모든 서비스 알림을 시간순으로 표시한다.

각 서비스 탭에서는 해당 서비스 알림만 표시한다.

서비스별 탭 안에서 다시 group by를 넣는 것은 작은 팝오버 안에서는 과할 수 있다. group by는 `전체` 탭에서 서비스별 묶음 표시가 필요해질 때만 고려하는 것이 좋다.

초기 구현은 `전체 / 블로그 / 피드` 3개 탭이 적당하다. 아직 메모, 일정, 가계부는 비활성 서비스이므로 탭에 먼저 노출하면 빈 화면만 생길 수 있다.

# 검색화면 로고 애니메이션 적용 범위

> 로고가 이상해 플랫폼 홈화면의 로고는 애니메이션 작동하는데, 상단바랑 검색화면의 로고는 애니메이션이 동작하지 않아

## 답변

현재 로고 컴포넌트 자체의 문제가 아니라 사용처에서 애니메이션을 명시적으로 꺼둔 상태다.

- 플랫폼 홈: `<BrandLogo size="lg" />`
  - `isAnimated` 기본값이 `true`라 애니메이션 동작
- 상단바: `<BrandLogo isAnimated={false} size="sm" />`
  - 명시적으로 애니메이션 꺼짐
- 검색화면: `<BrandLogo isAnimated={false} size="md" />`
  - 명시적으로 애니메이션 꺼짐

따라서 검색화면 로고 애니메이션을 켜려면 검색 오버레이에서 사용하는 `BrandLogo`의 `isAnimated={false}`만 제거하면 된다.

상단바는 페이지마다 계속 보이는 영역이라 애니메이션이 계속 재생되면 산만할 수 있으므로 별도 판단이 필요하다.

> 검색화면만 켜두자

## 구현 방향

- `TopBarActions.tsx`의 검색 오버레이 로고만 애니메이션을 켠다.
- 현재 `<BrandLogo isAnimated={false} size="md" />`를 `<BrandLogo size="md" />`로 변경한다.
- `AppTopBar.tsx`의 상단바 로고는 그대로 둔다.
- 상단바 로고는 계속 애니메이션이 꺼진 상태를 유지한다.

## 제외 범위

- 상단바 로고 애니메이션 활성화
- 플랫폼 홈 로고 변경
- `BrandLogo` 컴포넌트 자체 구조 변경
