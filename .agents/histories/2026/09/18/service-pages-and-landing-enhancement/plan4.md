# 상단바 로그인 액션 변경

> 로그인했을때 상단바의 내 정보를 로그아웃으로 변경

## 답변

현재 상단바 액션은 로그인 상태일 때 `내 정보` 텍스트와 `/me` 링크를 사용하고 있다.

요구사항은 로그인 상태에서 상단바 액션을 `로그아웃`으로 표시하는 것이다.

현재 프로젝트는 실제 인증/로그아웃 API가 연결된 상태가 아니므로, 우선 UI 레벨의 임시 로그아웃 액션으로 처리한다.

## 구현 방향

- `TopBarActions.tsx`에서 로그인 상태 라벨을 `내 정보`에서 `로그아웃`으로 변경한다.
- 로그인 상태 링크는 `/me` 대신 플랫폼 홈 `/`로 보낸다.
- 비로그인 상태의 `로그인` 라벨과 `/login` 링크는 유지한다.

## 제외 범위

- 실제 로그아웃 API 호출
- 세션/토큰 삭제
- mock auth 쿼리 파라미터 정리 로직
- 로그아웃 후 toast 또는 안내 메시지

# 피드 툴바 추적 탭 아이콘 재검토

> 피드 툴바의 추적을 관찰로 바꾸고 망원경은 다른 망원경 없나? 망원경처럼 안생김

## 답변

기존 `추적` 라벨과 `telescope` 아이콘은 의미 전달이 약하다.

처음에는 `관찰` 라벨과 `eye` 아이콘을 대안으로 제안했다. `관찰`은 방송/가격/관심 흐름을 지켜본다는 의미가 자연스럽고, 작은 하단 탭에서는 눈 아이콘이 망원경보다 알아보기 쉽다.

> 쌍안경으로 변경

## 답변

`관찰` 라벨은 유지하고, 아이콘만 `eye`에서 `binoculars`로 교체한다.

쌍안경 아이콘은 망원경보다 관찰 의미가 직접적으로 전달된다.

> 그냥 추적으로 바꾸고 막대그래프 아이콘

## 답변

최종 방향은 라벨을 다시 `추적`으로 되돌리고, 아이콘은 막대그래프 계열로 변경하는 것이다.

`barChart` 아이콘은 추적, 변화, 상태 확인 의미가 작은 하단 탭에서도 잘 읽힌다.

## 구현 방향

- `FeedView.tsx`
  - 피드 하단 툴바 라벨을 `추적`으로 설정한다.
  - 아이콘을 `barChart`로 설정한다.
- `Icon.tsx`
  - `barChart` 아이콘을 추가한다.
  - 더 이상 사용하지 않는 `binoculars` 아이콘을 제거한다.

## 제외 범위

- 피드 내부의 `추적 중인 항목` 문구 변경
- 피드 모델의 `trackingItems` 네이밍 변경
- 실제 추적 화면 라우팅 구현
- 추적 데이터 시각화 구현

# 로그인 플랫폼 홈 서비스별 피드 카드 추가

> 플랫폼홈 로그인상태 메인페이지에서 내 피드라는 카드 아래에 서비스별 피드 카드도 추가

## 답변

로그인 상태 플랫폼 홈의 `내 피드` 카드 아래에 서비스별 피드 카드를 추가한다.

처음에는 `내 피드` 카드 안에 서비스 목록을 넣는 방식도 고려할 수 있었지만, 요구사항은 별도 카드들을 같은 레벨로 추가하는 것이다.

> 내 피드 카드 안에 넣는게 아니라, 내 피드라는 카드와 동등한 ㄹ레벨로 서비스 카드들을 만드는거임

## 답변

구조는 `내 피드` 카드와 같은 sibling 레벨에 서비스별 카드를 추가하는 방식으로 잡는다.

현재:

- 로그인 플랫폼 홈
  - `내 피드` 카드

변경 후:

- 로그인 플랫폼 홈
  - `내 피드` 카드
  - `블로그` 카드
  - `피드` 카드
  - `메모` 카드
  - `일정` 카드
  - `가계부` 카드

## 구현 방향

- `MemberServiceFeedSection`에서 기존 `내 피드` 카드 구조는 유지한다.
- `PlatformHomeView`에서 `viewModel.services`를 `MemberServiceFeedSection`으로 전달한다.
- `MemberServiceFeedSection`은 `services`를 받아 `내 피드` 카드 아래 같은 레벨로 서비스 카드 grid를 렌더링한다.
- 서비스 순서는 기존 view model 순서인 `블로그 / 피드 / 메모 / 일정 / 가계부`를 유지한다.
- 활성 서비스는 바로가기 가능한 카드로 표시한다.
- 준비 중 서비스는 `준비 중` 상태를 표시한다.

## 제외 범위

- 서비스별 실제 피드 API
- 각 서비스별 상세 피드 화면
- 준비 중 서비스 라우팅
- 카드 클릭 이벤트 고도화

# 로그인 플랫폼 홈 서비스별 대형 피드 카드 재설계

> 서비스별 카드안에 데이터를 많이 넣을거기 때문에 카드가 커야함 위의 전체피드 카드처럼.
>
> 블로그에는 내가 쓴글, 내가 쓴 댓글, 팔로워수, 팔로잉수 카운팅 카드가 안에 중첩되고, 그 아래에 알림들이 카드들로 4개 정도 나열.
>
> 피드에는 관찰중인 아이템수, 관찰중인 스트리머수 놓고 밑에 알림 카드들로 4개정도 나열.
>
> 이런식으로 구성할거임 서비스별 카드를

## 답변

현재 추가한 서비스별 카드는 런처/요약 카드에 가까워서, 앞으로 카드 내부에 많은 데이터를 담기에는 작다.

방향을 `내 피드` 카드와 동등한 크기의 서비스별 대형 피드 카드로 바꾸는 것이 맞다.

## 목표 구조

- `내 피드` 카드
  - 기존 전체 활동 요약 유지
- `블로그` 대형 카드
  - 상단: 서비스명, 상태, 바로가기
  - 카운팅 카드 4개
    - 내가 쓴 글
    - 내가 쓴 댓글
    - 팔로워 수
    - 팔로잉 수
  - 하단: 블로그 알림 카드 4개
- `피드` 대형 카드
  - 상단: 서비스명, 상태, 바로가기
  - 카운팅 카드 2개
    - 관찰 중인 아이템 수
    - 관찰 중인 스트리머 수
  - 하단: 피드 알림 카드 4개
- `메모 / 일정 / 가계부`
  - 현재는 준비 중 대형 카드로 둔다.
  - 나중에 각 도메인 데이터 구조가 잡히면 같은 패턴으로 확장한다.

## 구현 방향

- `MemberServiceFeedSection`의 현재 작은 서비스 카드 grid를 제거한다.
- `MemberServiceFeedSection` 내부에 임시 view data를 둔다.
- 예시 데이터 구조:
  - `id`
  - `name`
  - `href`
  - `status`
  - `iconName`
  - `tone`
  - `metrics`
  - `notifications`
- 서비스별 카드는 `rounded-3xl border bg-surface p-5` 형태로 `내 피드` 카드와 비슷한 크기와 밀도를 가진다.
- 내부 카운팅 카드는 `bg-surface-strong`을 사용해 중첩 카드 느낌을 낮은 대비로 표현한다.
- 알림은 `grid gap-3`로 4개 카드가 나열되게 한다.
- 카드 안의 카드가 많아질 수 있으므로 지나치게 답답해 보이지 않도록 여백과 대비를 조절한다.

## 제외 범위

- 실제 서비스별 피드 API
- 실제 알림 API
- 서비스별 상세 피드 화면
- 메모, 일정, 가계부의 실제 데이터 구조
- 카드 클릭 이벤트 고도화

# 서비스별 대형 피드 카드 hover 범위 조정

> 서비스 카드위에 hover 지우고 서비스 카드 안 요소별 카드에 hover넣자

## 답변

현재 활성 서비스 대형 카드는 카드 전체가 `Link`라서 최상위 서비스 카드 전체에 hover 효과가 걸린다.

요구사항은 대형 서비스 카드 자체가 반응하는 것이 아니라, 카드 내부의 요소별 카드가 반응하도록 바꾸는 것이다.

## 구현 방향

- 활성 서비스도 최상위는 `article`로 렌더링한다.
- 대형 서비스 카드 최상위의 `hover:border-primary/40`, `hover:bg-surface-strong` 효과를 제거한다.
- 서비스 이동은 상단 우측의 작은 `바로가기` 링크로 제공한다.
- 준비 중 서비스는 상단 우측에 `준비 중` badge를 유지한다.
- 내부 지표 카드에 hover 효과를 추가한다.
- 내부 알림 카드에 hover 효과를 추가한다.

## 제외 범위

- 서비스별 상세 라우트 추가
- 지표 카드별 실제 상세 이동
- 알림 카드별 실제 상세 이동

# 로그인 플랫폼 홈 내정보 프로필 카드 배치

> 딱하나만 더하자 로그인시 플랫폼 홈에서 서비스 밑에 카운팅이랑 내피드 대신에 내정보 (프로필) 넣자

## 답변

로그인 상태 플랫폼 홈에서 서비스 런처 아래에 표시되던 오늘 요약 카운팅과 `내 피드` 카드를 제거하고, 그 자리에 내정보 프로필 카드를 배치한다.

서비스별 대형 피드 카드는 유지한다.

## 구현 방향

- `MemberServiceFeedSection`에서 상단 `todaySummaries` 카운팅 렌더링을 제거한다.
- `MemberServiceFeedSection`에서 `내 피드` 카드 렌더링을 제거한다.
- 같은 위치에 프로필 카드 섹션을 추가한다.
- 프로필 카드에는 다음 정보를 표시한다.
  - 사용자 아바타
  - 닉네임
  - 이메일
  - 설명
  - `/me` 바로가기
- 현재 실제 사용자 API가 없으므로 임시 프로필 데이터를 사용한다.
- 서비스별 대형 피드 카드 구조는 유지한다.
- `todaySummaries`, `recentActivities` props는 더 이상 사용하지 않으면 제거한다.
- `PlatformHomeView`에서 불필요한 props 전달도 제거한다.

## 제외 범위

- 실제 회원 API 연동
- 실제 프로필 수정 기능
- 마이페이지 데이터와 플랫폼 홈 프로필 데이터의 공통 모델화
- 서비스별 대형 피드 카드 구조 변경

# 로그인 플랫폼 홈 내정보 카드 섹션 헤더 추가

> 내정보 카드 위에도 텍스트 달자

## 답변

현재 로그인 플랫폼 홈에서 `서비스별 피드` 섹션에는 섹션 라벨과 제목이 있지만, `내정보` 프로필 카드는 바로 카드가 노출된다.

아래 서비스별 피드 섹션과 화면 리듬을 맞추기 위해 내정보 카드 위에도 텍스트를 추가한다.

## 구현 방향

- 프로필 카드를 `grid gap-3` 섹션으로 감싼다.
- 섹션 상단에 작은 라벨과 제목을 추가한다.
- 작은 라벨은 `내정보`로 표시한다.
- 제목은 `계정과 서비스 사용 상태`로 표시한다.
- 기존 프로필 카드 내부 정보와 `/me` 바로가기는 유지한다.

## 제외 범위

- 프로필 데이터 구조 변경
- 마이페이지 화면 변경
- 실제 회원 API 연동

# 상단 알림 팝오버 바깥 클릭 닫기

> 상단 알림버튼 눌러서 알림창 떴을때  맨화면 누르면 알림창 꺼지게 해줘.

## 답변

현재 알림 팝오버는 알림 버튼을 다시 눌러야 닫히는 구조다.

요구사항은 알림 팝오버가 열린 상태에서 화면의 빈 영역을 클릭하면 알림창이 닫히도록 만드는 것이다.

## 구현 방향

- 알림 팝오버가 열렸을 때 화면 전체를 덮는 투명 backdrop을 추가한다.
- backdrop 클릭 시 `setIsNotificationOpen(false)`를 호출한다.
- 알림 팝오버 내부 클릭은 닫히지 않도록 `stopPropagation`을 적용한다.
- 검색 오버레이처럼 화면을 어둡게 하지 않고 투명 클릭 영역만 둔다.
- 기존 알림 팝오버 위치와 스타일은 유지한다.

## 제외 범위

- Esc 키 닫기
- 포커스 트랩
- 알림 실제 API
- 알림 읽음 처리

# 상단 알림 팝오버 portal 렌더링 전환

> 상단바 내에서 다른곳 누르면꺼지는데 메인화면쪽 빈화면 누르면 안꺼짐

## 답변

현재 알림 backdrop은 `TopBarActions` 내부에서 렌더링된다.

`fixed inset-0`를 사용하더라도 상단바 내부 DOM과 stacking context 영향으로 메인 화면 전체 클릭 영역을 안정적으로 덮지 못하는 상태로 보인다.

검색 오버레이와 같은 방식으로 알림 backdrop과 팝오버도 `document.body`에 portal 렌더링하는 것이 맞다.

## 구현 방향

- 알림 backdrop과 팝오버를 `createPortal(..., document.body)`로 렌더링한다.
- backdrop은 `fixed inset-0`로 화면 전체를 덮는다.
- backdrop 클릭 시 `setIsNotificationOpen(false)`를 호출한다.
- 팝오버 내부 클릭은 `stopPropagation`으로 닫히지 않게 한다.
- 팝오버 위치는 기존 우측 상단 근처 고정값을 유지한다.
- 화면은 어둡게 하지 않고 `bg-transparent`를 유지한다.
