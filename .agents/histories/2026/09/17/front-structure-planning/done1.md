# 개요

- 2026-09-17 프론트 구성 기획 작업을 마무리한다.
- `choimory.dev`를 단일 SNS 앱이 아니라 여러 하위 서비스를 담는 플랫폼으로 보는 방향으로 화면 구조를 재정리했다.
- 플랫폼 홈, blog, 인증, 마이페이지, 공통 레이아웃의 1차 화면 기반을 구현했다.
- 실제 API 연동은 제외하고, ViewModel과 mock auth 기반으로 화면 구조를 먼저 잡았다.

# 완료된 작업

## 플랫폼 구조 전환

- 기존 인스타그램 단일 앱에 가까운 화면 방향을 플랫폼형 구조로 재정의했다.
- `community` 명칭과 구조를 `blog`로 전환했다.
- `/community` 대신 `/blog`를 사용하도록 라우트와 feature 구조를 정리했다.
- 플랫폼 하위 서비스 후보를 다음 기준으로 정리했다.
  - 블로그
  - 메모
  - 피드
  - 가계부
  - 일정

## 공통 UI와 레이아웃

- `BrandLogo` 공통 컴포넌트를 추가했다.
- 로고 표기를 `{choimory.dev()}`로 정리했다.
- 로고 애니메이션은 wave 느낌이 아니라 타자기처럼 글자가 나타나는 방식으로 변경했다.
- 로고 색상 분리를 복구했다.
- 상단바에서는 로고 애니메이션을 끄고, 플랫폼 홈 메인 로고에서는 애니메이션을 유지했다.
- 모바일 320px에서 상단바가 깨지지 않도록 검색/알림 숨김, 로그인 버튼 보호, `/ blog` 표시 구조를 보정했다.
- 768px 태블릿 폭에서 좌우 여백이 사라지지 않도록 보정했다.
- `AppContent`를 추가하여 서비스 화면 중앙 레이아웃을 프로젝트 공통으로 통합했다.
- 플랫폼 홈, blog, 마이페이지는 모두 `AppContent` 기반 wide 레이아웃을 사용한다.
- `AppTopBar`와 `BottomNavigation`의 기본 폭을 wide로 통일했다.
- 기존 `WideContent`, `NarrowContent`는 제거했다.

## 인증과 마이페이지 화면

- `/login` 화면을 추가했다.
- `/signup` 화면을 추가했다.
- `/me` 마이페이지 화면을 추가했다.
- 로그인 화면에 회원가입 진입 버튼을 명확히 추가했다.
- 로그인 화면에 네이버, 카카오, 구글 소셜 로그인 버튼을 추가했다.
- 마이페이지에는 다음 항목을 화면 구조로 추가했다.
  - 프로필 요약
  - 개인정보 변경
  - 사이트 설정
  - 2차 인증
  - 회원 탈퇴

## 플랫폼 홈

- 플랫폼 홈을 `choimory.dev` 메인, 검색바, 서비스 런처, 비회원/회원 분기 영역으로 구성했다.
- 서비스 런처는 하나의 카드 안에 아이콘 버튼 목록으로 표시한다.
- 서비스 런처는 좌우 화살표로 이동할 수 있게 했다.
- 검색바에서 불필요한 `N`, `AI` 요소를 제거하고 돋보기/검색 버튼 중심으로 정리했다.
- 플랫폼 홈에 `authStatus: 'guest' | 'member'` 분기 구조를 추가했다.
- 비회원 상태에서는 서비스 허브형 소개와 로그인/회원가입 CTA를 보여준다.
- 회원 상태에서는 오늘 요약과 최근 활동 기반의 서비스 피드 뼈대를 보여준다.

## blog 화면

- blog 화면에도 `authStatus: 'guest' | 'member'` 분기 구조를 추가했다.
- 비회원 상태에서는 blog 소개, 공개 글 미리보기, 로그인/회원가입 CTA를 보여준다.
- 회원 상태에서는 기존 피드 화면을 유지하며 다음 요소를 표시한다.
  - 피드 필터
  - 글쓰기 버튼
  - 글 작성 진입 영역
  - 게시글 카드
- blog 비로그인 소개 카드 상단은 `choimory.dev / blog 시작하기` 텍스트로 표시한다.
- blog 화면도 플랫폼 홈과 동일한 wide 레이아웃으로 맞췄다.
- 320px에서도 상단바의 `/ blog` 링크가 사라지지 않도록 했다.

# 현재 남은 작업

## blog 하단 툴바와 검색 UX 정리

현재 blog 하단 툴바는 다음 항목을 사용한다.

- 피드
- 인기
- 작성
- 홈

아직 확정되지 않은 항목:

- 플랫폼 홈
- blog 홈
- 내 blog 홈
- 검색
- 글쓰기

검색을 상단 아이콘으로 둘지, 별도 검색 화면으로 둘지 결정해야 한다.

## 회원용 플랫폼 홈 다듬기

현재 회원용 플랫폼 홈은 오늘 요약과 최근 활동 피드의 뼈대 수준이다.

남은 작업:

- 서비스별 요약 구체화
- 자주 쓰는 서비스와 최근 사용 서비스 구분
- 알림 피드와 최근 활동 피드 역할 분리
- 메모, 피드, 가계부, 일정 요약 데이터 표현 방식 정리

## 서비스별 라우트 뼈대 추가

서비스 런처에는 후보 서비스가 보이지만, 아직 실제 화면이 없는 서비스가 있다.

남은 라우트:

- `/memo`
- `/feed`
- `/account-book`
- `/schedule`

각 서비스의 첫 화면이 비로그인/로그인 상태에서 어떻게 달라질지도 함께 정해야 한다.

## 실제 인증 연동 전 구조 정리

현재 인증 상태는 URL query 기반 mock 구조로 확인한다.

예시:

- `/?auth=member`
- `/blog?auth=member`

남은 작업:

- 실제 세션 상태를 어디서 읽을지 결정
- `authStatus`를 ViewModel에 직접 넣는 방식을 유지할지 검토
- 공통 session model 또는 provider 도입 여부 검토
- 상단바, 플랫폼 홈, blog, 마이페이지가 같은 인증 상태를 바라보게 만들기

## 실제 기능 연동

이번 작업에서는 실제 기능 연동을 제외했다.

남은 실제 연동:

- 로그인 API
- 회원가입 API
- 소셜 로그인 OAuth
- 마이페이지 저장
- 테마 저장
- 2차 인증
- 회원 탈퇴

## 비로그인 랜딩 추가 고도화

비로그인 랜딩은 1차로 서비스 허브형 안내까지 개선했다.

다만 초기 계획에 있던 더 화려한 HTML 랜딩 수준까지는 아직 가지 않았다.

필요하면 다음 단계에서 플랫폼 홈과 blog 비로그인 화면의 시각적 완성도를 더 높일 수 있다.
