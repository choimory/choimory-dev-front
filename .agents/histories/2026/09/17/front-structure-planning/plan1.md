# 개요

- choimory-dev라는 하나의 큰 사이트안에서 여러 서비스들을 도메인별로 나뉘어서 제공할 예정임
- choimory-dev
  - 회원가입, 회원간 교류, 포스팅 (인스타그램 같은)
  - 개인 메모장
  - 스트리머 알림 (인터넷 방송 플랫폼에서 특정 스트리머의 방송 시작, 채팅 등등을 주시하면서 이벤트시 알려줌)
  - 가격 알림 (내가 원하는 상품의 가격이 특정 가격 밑으로 내려가면 알림)
  - 그 외 내가 써먹고 싶은 아이템이 생길때마다 개발해서 choimory-dev 하위 서비스로 붙일 예정
- 이런식으로 choimory-dev라는 기본 사이트들 만들고, 추가하고 싶은 서비스가 생길때마다 계속 붙이도록 할건데, 그럴려면 화면을 어떻게 구성하면 좋을까

# 현재 화면 구성 분석

> 지금 화면 구성 분석해봐. 지금은 약간 인스타그램 하나만 보고 만든 화면일거임

## 답변

현재 화면 구성은 말씀대로 "인스타그램 하나를 염두에 둔 모바일 앱 쉘"에 가깝다.

핵심 구조는 상단 헤더, 중앙 콘텐츠, 하단 네비게이션으로 이루어져 있으며, 하단 네비게이션도 홈, 검색, 등록, 알림, 프로필처럼 SNS/피드 서비스에 자연스러운 항목으로 구성되어 있다.

## 현재 화면 구조

- 전체 레이아웃은 `ScreenLayout` 기준으로 상단 헤더, 중앙 콘텐츠, 하단 네비게이션으로 구성되어 있음.
- `AppHeader`는 `choimory-dev` 서비스명과 우측 액션 영역, 테마 토글을 제공함.
- `BottomNav`는 홈, 검색, 등록, 알림, 프로필 아이콘으로 구성되어 있음.
- `/home` 화면은 사용자 요약 카드, 샘플 섹션 카드, 기능 강조 영역으로 구성되어 있음.
- 인증 화면은 앱처럼 가운데 폼 하나를 배치하는 단순한 구조로 되어 있음.

## 현재 구성의 한계

- `홈 / 검색 / 등록 / 알림 / 프로필` 구조는 콘텐츠/SNS 도메인 중심의 하단 탭임.
- 여러 서비스를 붙이는 플랫폼이 되려면, 하단 네비게이션이 특정 서비스의 행동이 아니라 플랫폼 전체의 주요 영역을 가리켜야 함.
- 지금 `/home`은 사용자 활동 요약과 샘플 콘텐츠 중심이라, 사용자가 어떤 하위 서비스로 들어갈 수 있는지 보여주는 런처 역할이 약함.
- `검색`과 `등록`은 서비스마다 의미가 달라질 수 있음.
  - 커뮤니티에서는 게시글 검색/작성
  - 메모장에서는 메모 검색/작성
  - 가격 알림에서는 상품 검색/알림 생성
  - 스트리머 알림에서는 스트리머 검색/알림 생성
- 따라서 검색과 등록을 전역 하단 탭으로 고정하면, 서비스가 늘어날수록 의미가 흐려질 가능성이 큼.

## 방향성

- `choimory-dev`를 하나의 SNS 앱으로 볼지, 여러 서비스를 담는 플랫폼으로 볼지 먼저 정해야 함.
- 현재 기획 의도는 여러 하위 서비스를 계속 붙이는 것이므로, 플랫폼형 구조가 더 적합해 보임.
- SNS 기능은 `choimory-dev` 자체의 중심 구조라기보다, 여러 하위 서비스 중 하나인 커뮤니티/피드 서비스로 분리하는 편이 확장에 유리함.

## 추천 화면 구조

- `/home`
  - 오늘 요약
  - 자주 쓰는 서비스
  - 최근 활동
  - 전체 서비스 목록 일부
- `/services`
  - 메모장
  - 스트리머 알림
  - 가격 알림
  - 커뮤니티/SNS
  - 이후 추가되는 하위 서비스들
- `/notifications`
  - 모든 서비스의 알림 통합
  - 스트리머 방송 시작, 가격 하락, 댓글/팔로우 등 도메인별 알림을 한 곳에서 확인
- `/me`
  - 프로필
  - 계정 설정
  - 내 활동
  - 내가 사용하는 서비스 설정
- 각 서비스별 독립 경로
  - `/memo`
  - `/stream-alerts`
  - `/price-alerts`
  - `/community`

## 하단 네비게이션 후보

- 플랫폼형 하단 탭 예시
  - 홈
  - 서비스
  - 알림
  - 내 공간
- 또는 조금 더 단순하게
  - 홈
  - 서비스
  - 알림
  - 프로필

## 결론

- 현재 화면은 단일 모바일 SNS 앱의 출발점으로는 괜찮음.
- 하지만 `choimory-dev`를 여러 서비스를 계속 붙이는 상위 플랫폼으로 키우려면, `/home`을 피드가 아니라 서비스 대시보드로 재정의하는 것이 좋음.
- 하단 네비게이션도 인스타그램식 `검색/등록` 중심에서 플랫폼형 `서비스/알림/내 공간` 중심으로 바꾸는 방향이 좋아 보임.

# 플랫폼 홈 화면 목업

> 니가 생각하는 화면 모양을 시각적으로 보고 싶어. html을 만들던 뭐를 만들던 나에게 시각적으로 보여주면 좋겠어

## 답변

`choimory-dev`를 단일 SNS 앱이 아니라 여러 서비스를 담는 개인 플랫폼으로 보고, 플랫폼 홈 화면 목업을 작성함.

목업 파일:

- `platform-home-mockup.html`

## 화면 방향

- 첫 화면은 특정 서비스의 피드가 아니라, 여러 서비스로 들어가는 개인 포털 홈으로 구성함.
- 상단에는 `choimory-dev` 브랜드, 통합 검색, 알림, 프로필을 둠.
- 본문에는 오늘 요약, 자주 쓰는 서비스, 최근 활동, 중요 알림을 배치함.
- 자주 쓰는 서비스에는 개인 메모장, 스트리머 알림, 가격 알림, 커뮤니티/SNS를 카드 형태로 보여줌.
- 하단 또는 주요 네비게이션은 `홈 / 서비스 / 알림 / 내 공간`처럼 플랫폼 전체의 큰 영역을 가리키는 쪽이 적합함.
- 핵심은 사용자가 로그인 후 곧바로 피드에 빠지는 것이 아니라, 현재 자신이 사용할 수 있는 하위 서비스들을 빠르게 훑고 진입하는 것.

# 커뮤니티 서비스 진입 후 화면

> 그다음엔 인스타 서비스로 들어갔다고 치면 그때 화면은?

## 답변

플랫폼 홈에서 커뮤니티/SNS 서비스로 들어가면, 전역 플랫폼 구조는 최소한으로 유지하고 내부 화면은 피드 중심으로 전환하는 형태가 좋음.

목업 파일:

- `community-service-mockup.html`

## 화면 방향

- 상단에는 `choimory-dev / 커뮤니티`처럼 현재 위치를 알 수 있는 맥락을 남김.
- 커뮤니티 내부에서는 피드, 인기, 팔로잉, 내 글 같은 SNS 서비스 전용 메뉴를 사용함.
- 글쓰기, 피드 필터, 게시글 카드, 좋아요, 댓글, 공유, 저장 같은 기능은 커뮤니티 서비스 안에서만 깊게 다룸.
- 우측 영역에는 인기 태그, 추천 사용자처럼 커뮤니티에 특화된 보조 정보를 둘 수 있음.
- 플랫폼 전체의 `서비스`, `가격 알림`, `메모장` 같은 메뉴와 커뮤니티 내부의 `피드`, `팔로잉`, `글쓰기`는 역할이 다르므로 구분하는 것이 좋음.
- 즉, `choimory-dev`는 상위 플랫폼이고, 커뮤니티는 그 안에 들어간 하나의 서비스로 취급함.

# 커뮤니티 모바일 화면

> 이걸 모바일 느낌으로 하면 ?

## 답변

모바일에서는 상단에 커뮤니티 서비스 안에 들어와 있다는 맥락만 남기고, 본문은 거의 SNS 피드처럼 가볍게 구성하는 것이 자연스러움.

목업 파일:

- `community-mobile-mockup.html`

## 화면 방향

- 상단에는 뒤로가기, `커뮤니티`, 검색, 알림 정도만 둠.
- 서비스 내부 탭은 `추천 / 팔로잉 / 최신 / 인기`처럼 가로 칩 형태로 배치함.
- 본문은 작성 박스와 게시글 피드 중심으로 구성함.
- 게시글은 프로필, 작성자, 시간, 이미지, 좋아요/댓글/공유/저장 액션, 본문, 댓글 보기 순서로 구성함.
- 하단 네비게이션은 커뮤니티 내부 행동인 `피드 / 인기 / 팔로잉 / 내 글 / 홈` 또는 `피드 / 인기 / 작성 / 팔로잉 / 홈` 형태가 가능함.
- 모바일에서는 플랫폼 메뉴를 많이 노출하기보다, 현재 들어온 서비스의 사용성에 집중하는 편이 좋음.

# PC에서도 모바일 같은 좁은 화면

> pc버전도 모바일처럼 (지금 프로젝트 레거시처럼) 좌우 마진 넣고 좀 길쭉한 모양새로 약간 모바일 처럼으로 하고 싶음

## 답변

PC에서도 일반 웹 대시보드처럼 화면을 넓게 다 쓰지 않고, 중앙 피드 폭을 고정해서 모바일 앱 같은 감각을 유지하는 방향이 좋음.

목업 파일:

- `community-desktop-narrow-mockup.html`

## 화면 방향

- 데스크톱에서도 콘텐츠 폭을 약 `560px` 정도로 제한하고 중앙에 배치함.
- 좌우는 넓은 여백으로 두어 피드 집중도를 높임.
- 기존 프로젝트의 모바일 앱 같은 레거시 감각을 유지하려면, PC에서도 `max-w-lg` 계열의 중앙 레이아웃을 유지하는 것이 어울림.
- 상단 헤더는 전체 폭을 쓰되, 내부 콘텐츠 정렬은 중앙 피드 폭과 맞추는 것이 좋음.
- 필요하다면 왼쪽 여백에 작은 아이콘 레일만 배치해 플랫폼 홈, 피드, 글쓰기 같은 빠른 이동을 제공할 수 있음.
- 하단 네비게이션도 모바일처럼 중앙 피드 폭에 맞춰 둘 수 있음.
- 이 방향은 인스타그램 웹처럼 너무 넓은 3단 레이아웃으로 가지 않고, 모바일 앱을 PC에서 그대로 확장한 느낌을 줌.
