# plan4 이후 남은 작업

## 플랫폼 홈 분기

플랫폼 홈은 로그인 상태에 따라 화면 구성이 달라져야 한다.

비로그인 사용자:

- 현재처럼 랜딩 또는 서비스 소개 중심 화면을 보여준다.
- 로그인/회원가입 CTA를 제공한다.
- 서비스 런처는 둘러보기 성격으로 유지한다.

로그인 사용자:

- 사용자의 서비스별 피드 요약을 보여준다.
- 최근 활동 또는 알림 요약을 보여준다.
- 서비스 런처는 실제 사용자의 진입점 역할을 한다.

현재 실제 로그인 상태는 없으므로, 우선 `PlatformHomeViewModel`에 `authStatus: 'guest' | 'member'` 같은 임시 값을 두고 분기 구조를 만든다.

## blog 화면 분기

blog 화면도 로그인 상태에 따라 화면 구성이 달라져야 한다.

비로그인 사용자:

- blog 서비스 소개를 보여준다.
- 지금 뜨거운 게시글 또는 인기글 피드를 보여준다.
- 로그인/회원가입 CTA를 제공한다.

로그인 사용자:

- 현재 구현된 피드 화면을 유지한다.
- 피드 필터, 글 작성 진입 영역, 게시글 카드를 보여준다.

`BlogViewModel`에도 `authStatus: 'guest' | 'member'` 같은 필드를 추가하여 분기 구조를 만든다.

## 서비스 목록 정리

현재 서비스 런처에는 더미 서비스가 섞여 있다.

1차 확정 후보:

- 블로그
- 메모
- 피드
- 가계부
- 일정

다음 작업에서는 서비스 목록을 위 후보 중심으로 정리한다.

필요하면 `isPlaceholder` 같은 필드를 두어 실제 서비스와 화면 확인용 더미 서비스를 구분한다.

## 플랫폼 랜딩페이지 고도화

현재 비회원 소개 섹션은 아직 카드형 소개에 가깝다.

`plan4.md`에서는 단순 카드형 랜딩이 아니라 HTML을 활용한 더 화려한 랜딩페이지 방향을 언급했다.

다만 랜딩페이지 디자인을 먼저 크게 키우기보다는, 플랫폼 홈의 `guest/member` 분기 구조를 먼저 만든 뒤 비회원 랜딩을 고도화하는 것이 좋다.

## blog 하단 툴바와 상단 검색 UX

현재 blog 하단 툴바는 다음 4개 항목을 사용한다.

- 피드
- 인기
- 작성
- 홈

남은 고민:

- 플랫폼 홈
- blog 홈
- 내 blog 홈
- 검색
- 글쓰기

하단 툴바에 모든 항목을 넣으면 복잡해지므로, 초기 방향은 하단 4개를 유지하는 것이다.

검색과 내 blog 홈은 상단 액션 또는 별도 라우트로 분리하는 편이 좋다.

## 아직 제외할 실제 기능 연동

다음 단계에서도 실제 기능 연동은 제외한다.

- 로그인 API
- 회원가입 API
- 소셜 로그인 OAuth
- 마이페이지 저장
- 테마 저장
- 2차 인증
- 회원 탈퇴

우선 화면 구조와 ViewModel 분기만 만든다.
