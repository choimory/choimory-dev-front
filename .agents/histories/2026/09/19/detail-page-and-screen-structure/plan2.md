# 개요

- 상세페이지 구상과 몇몇 수정사항 진행

## 플랫폼

- 공지사항
  - 글 목록 카드로 나오는거 오케이
  - 글 목록 카드 눌렀을때 글 상세보기 모달창 같은거로 뜨면 좋을듯?
- 서비스
  - 문제없음
- 내 공간
  - 툴바의 내 공간을 내 정보로 수정
  - 목록화면 오케이
  - 카드 내 버튼 눌렀을때 모달창 뜨면 좋을듯?
  - 개인정보 수정버튼 -> 개인정보 입력하는 모달창. 이메일은 변경불가하고, 나머지 닉네임과 자기소개는 바꿀수 있고 닉네임은 중복체크해야함 
  - 사이트 설정 -> 모달안에 설정별로 카드. 테마 설정은 light, dark, system 버튼 세개 radio
  - 2차인증 설정 -> 이메일 인증, 모바일(어플)인증 두개 radio인데 지금 모바일은 아직 미구현

## 블로그

- 포스트 상세페이지
  - 좋아요랑 댓글수 표시가 너무 크게 되어있음 (글목록처럼 이모지와 함께 조그맣게 표시하는게 깔끔할듯)
  - 상세보기 페이지는 좋아요, 북마크, 공유버튼이 없음
  - 댓글 카드가 너무 큰듯?
  - 댓글의 댓글은 어떻게 표시할것인지? 멘션이랑 (예시로 같이 만들어주셈)
  - 댓글에도 좋아요 넣기
- 인기
  - 위에 실시간 검색 순위 랭킹 표시 (순위 등락 애니메이션과 함께)
- 팔로잉
  - 내가 팔로잉하는 사람들 목록이랑 관리하는 내용이 위에 있으면 좋을듯
- 내 블로그
  - 내 블로그나 타인 아이디 눌러서 특정유저의 블로그 메인 이동했을시 그사람의 프로필(자기소개, 닉네임, 사진)과 팔로잉, 팔로워정보가 보이고 밑으로 글이 보여야할거같은데 그런 개인정보는 안보이고 글만 보임
- 인기는 맨 위에 검색순위 카드가 뜨고, 팔로잉은 맨 위에 나의 팔로잉 목록과 관리 카드가 뜨고, 내 블로그(및 타인 블로그)에는 프로필 카드가 맨위에 뜨면 일정하고 딱 좋겠네

## 피드

- 인기
  - 여기도 맨위에 인기 아이템 랭킹 카드 (순위등락 애니메이션과 함께)
  - 여기서 표시될것은 인기 아이템과 인기 스트리머들임. 이벤트 내용이 아니라 그냥 아이템과 스트리머만 표시되면 됨
  - 여기 랭킹은 등록이 잦은 아이템이나 가격변동이 심한 아이템 순위나 활동이 활발한 스트리머 순위 뭐 이런걸 표현할까 생각중
  - 아이템/스트리머를 구분해서 표현할까 섞어서 한 목록으로 표현할까 고민
  - 아이템을 누르면 아이템 상세 페이지(아이템 정보와 가격 추이 그래프가 나오는 상세화면), 스트리머를 누르면 스트리머 정보와 방송 추이나 이벤트 추이같은 상세화면으로 넘어감. 이 상세화면은 관찰메뉴에서도 쓰일거임 
- 관찰
  - 내가 등록해놓은 아이템/스트리머 목록들이 나오고 누르면 인기에 적은것과 같은 상세페이지로 이동
    - (아이템을 누르면 아이템 상세 페이지(아이템 정보와 가격 추이 그래프가 나오는 상세화면), 스트리머를 누르면 스트리머 정보와 방송 추이나 이벤트 추이같은 상세화면으로 넘어감. 이 상세화면은 인기메뉴에서도 쓰일거임)
  - 아이템/스트리머를 구분해서 표현할까 섞어서 한 목록으로 표현할까 고민
  - 여기는 인기쪽과 똑같이 내가 팔로잉한 아이템과 스트리머 목록만 나오게 할지 아니면 이벤트 내용도 보여도 될거같은데 어떨지 고민
- 내 피드
  - 여기 맨 위 카드엔 내가 등록한 아이템/스트리머수, 관찰중 수, 새 알림 수, 관심 항목수 (홈에 있는) 이런거 걸면 될듯 
  - 여기도 밑으로 내가 팔로잉 해놓은 아이템/스트리머 목록들이 나옴
  - 근데 추가 등록할 수 있는 버튼이 있어서 누르면 아이템/스트리머 등록을 진행할 수 있음
  - 그리고 카드를 누르면 그래프나 추세, 추이같은 상세정보가 나오는게 아니라 내 설정 정보가 나옴 (관찰 on/off, 삭제, 알림주기, 알림보낼 가격설정, 스트리머의 경우 방송알림on/off. 채팅알림on/off 등등)

# plan2 분석

> 분석시작

## 전체 방향

`plan2`는 1차로 연결된 화면을 실제로 쓸 수 있는 상세 UX로 다듬는 작업이다.

현재 1차 구현에서는 플랫폼, 블로그, 피드의 하단 메뉴와 주요 상세 라우트를 연결했다. 다만 실제 사용 흐름 관점에서는 아직 다음이 부족하다.

- 카드 클릭 시 모달 또는 상세 내용 표시
- 메뉴별 상단 특화 정보
- 상세 화면의 액션 버튼과 댓글 구조
- 피드의 아이템/스트리머 도메인 모델 구분
- 내 피드와 관찰 상세의 역할 분리

작업 범위가 넓으므로 한 번에 모두 구현하기보다 3덩어리로 나누는 것이 좋다.

## 1차로 바로 하기 좋은 범위

플랫폼, 마이페이지, 블로그 상세 화면은 지금 구조 위에 바로 얹기 좋다.

### 공지사항 상세 모달

현재 `PlatformNoticeView`는 카드 목록만 있고 클릭 동작이 없다.

구현 방향:

- 공지사항 카드를 클릭하면 상세 모달을 표시한다.
- 공지 데이터는 현재 컴포넌트 내부 상수로 있으므로 선택된 공지 상태만 추가하면 된다.
- 공지 상세 URL이 당장 필요하지 않으므로 라우트보다 모달이 적합하다.

### 마이페이지 하단 명칭 수정

현재 마이페이지 하단 네비게이션은 `내 공간`으로 표시된다.

구현 방향:

- `내 공간`을 `내 정보`로 변경한다.

### 마이페이지 설정 카드 모달

현재 `MeSettingCard`의 버튼은 동작이 없다.

구현 방향:

- `MeView`에서 선택된 setting id 상태를 관리한다.
- `MeSettingCard`에 `onClick` 계열 이벤트를 전달한다.
- 버튼 클릭 시 설정별 모달을 표시한다.
- 개인정보 수정 모달
  - 이메일은 변경 불가로 표시한다.
  - 닉네임과 자기소개는 수정 가능하게 표시한다.
  - 닉네임 중복체크 버튼을 배치한다.
- 사이트 설정 모달
  - 설정별 카드 구조로 표시한다.
  - 테마 설정은 `light`, `dark`, `system` radio 형태로 표시한다.
- 2차 인증 설정 모달
  - 이메일 인증과 모바일 인증 radio를 표시한다.
  - 모바일 인증은 아직 미구현 상태로 표시한다.
- 회원 탈퇴 모달은 위험 액션으로 별도 강조한다.

모달 컴포넌트는 우선 `features/me/components` 내부에 두는 것이 좋다. 다른 도메인에서도 모달이 필요해지면 그때 `shared/ui`로 승격하면 된다.

### 블로그 게시글 상세 UI 개선

현재 게시글 상세 화면은 좋아요/댓글 수가 큰 카드 2개로 표시되어 과하다.

구현 방향:

- 좋아요/댓글 수를 글 목록처럼 작은 액션 줄로 표시한다.
- 좋아요, 댓글, 북마크, 공유 버튼을 상세 화면에도 추가한다.
- 댓글 카드를 더 compact하게 만든다.
- 대댓글과 멘션 예시를 추가한다.
- 댓글에도 좋아요를 표시한다.

이 범위는 기존 라우트와 ViewModel을 크게 흔들지 않고 화면 품질을 올릴 수 있다.

## 2차로 하면 좋은 범위

블로그 메뉴별 상단 특화 카드가 2차 범위로 적합하다.

현재 `BlogMenuView`는 메뉴 종류별 제목만 바꾸고 같은 게시글 목록을 보여준다. 따라서 `menuKind`별 상단 섹션을 끼우는 방식이 자연스럽다.

### 블로그 인기

`/blog/popular` 상단에는 실시간 검색 순위 또는 인기 키워드 랭킹 카드를 둔다.

구현 방향:

- 순위 목록을 표시한다.
- 등락은 작은 badge나 화살표 느낌으로 표현한다.
- 과한 애니메이션보다는 작은 순위 등락 표시가 적합하다.

### 블로그 팔로잉

`/blog/following` 상단에는 내가 팔로잉하는 사람 목록과 관리 카드를 둔다.

구현 방향:

- 팔로잉 사용자 목록을 가로 카드 또는 compact list로 표시한다.
- 관리 진입 버튼을 제공한다.

### 내 블로그

`/blog/me` 상단에는 프로필 카드를 둔다.

구현 방향:

- 닉네임, 자기소개, 프로필 이미지 영역을 표시한다.
- 팔로잉, 팔로워 정보를 표시한다.
- 아래에는 기존 글 목록을 유지한다.

타인 블로그까지 생각하면 나중에 `/blog/users/[userId]` 같은 라우트가 필요할 수 있다.

## 3차로 설계가 더 필요한 범위

피드 쪽은 현재 모델을 먼저 정리하는 것이 좋다.

현재 피드 모델은 `observations`와 `activities` 정도만 있다. 하지만 `plan2`에서는 피드 대상이 명확히 두 종류다.

- 아이템
  - 가격 정보
  - 가격 추이 그래프
  - 목표 가격
- 스트리머
  - 방송 상태
  - 방송 추이
  - 이벤트 추이
  - 방송 알림
  - 채팅 알림

따라서 기존 `FeedObservationItem`을 그대로 키우기보다 `FeedWatchTarget` 같은 모델로 재정리하는 편이 좋다.

추천 방향:

- 인기/관찰 목록은 아이템/스트리머 대상 목록을 보여준다.
- 대상 클릭 시 `/feed/targets/[targetId]` 같은 공통 상세 화면으로 이동한다.
- 공통 상세 화면은 아이템과 스트리머 타입에 따라 다른 정보를 보여준다.
  - 아이템: 아이템 정보, 가격 추이 그래프, 목표 가격
  - 스트리머: 스트리머 정보, 방송 추이, 이벤트 추이
- 내 피드에서 대상 클릭 시에는 그래프 상세가 아니라 내 설정 상세 또는 설정 모달로 이동한다.
- 내 피드 상단에는 등록 수, 관찰 중, 새 알림, 관심 항목 요약 카드를 표시한다.
- 내 피드에는 추가 등록 버튼을 제공한다.
- 추가 등록은 모달 또는 `/feed/observations/new` 같은 별도 화면으로 확장할 수 있다.

## 결정 포인트

### 피드 인기/관찰 목록에서 아이템과 스트리머를 섞을지 여부

1차 구현에서는 섞은 목록과 `아이템`, `스트리머` badge를 사용하는 것이 좋아 보인다.

이유:

- 화면이 단순하다.
- 현재 데이터가 많지 않은 mock 단계에 잘 맞는다.
- 나중에 탭을 추가하기 쉽다.

### 공지사항 상세를 모달로 할지 라우트로 할지 여부

현재는 모달이 적합하다.

이유:

- `plan2`에서 모달창을 원한다고 명시되어 있다.
- 공지 상세 URL이 아직 반드시 필요하지 않다.
- 목록 화면 컨텍스트를 유지하는 것이 자연스럽다.

공지 공유 URL이 필요해지면 나중에 `/notice/[noticeId]`로 분리하면 된다.

### 마이페이지 설정 모달 위치

현재는 `features/me/components` 내부에 두는 것이 적합하다.

이유:

- 아직 마이페이지 전용 모달이다.
- 공통 모달 규격이 프로젝트에 정해져 있지 않다.
- 다른 도메인에서도 같은 모달 패턴이 필요해지면 `shared/ui`로 승격할 수 있다.

### 공통 depth 라벨 표기

`{choimory.dev()}/welcome`, `blog/comments` 같은 개발자스러운 depth 표기는 이번 구현에 넣지 않는 것이 맞다.

이유:

- `plan2`에서 진행하지 말고 나중에 맛보기로 보고 결정하자고 되어 있다.
- 이미 일부 화면에는 비슷한 표기가 있고 일부에는 없어서, 별도 디자인 정리 작업으로 다루는 편이 좋다.

## 추천 구현 순서

1. 플랫폼 공지 모달, 마이페이지 모달, 하단 `내 정보` 명칭 수정
2. 블로그 상세 화면 다듬기와 댓글/대댓글 예시 추가
3. 블로그 인기, 팔로잉, 내 블로그 상단 특화 카드 추가
4. 피드 모델을 아이템/스트리머 target 기준으로 재설계
5. 피드 인기, 관찰, 내 피드 화면 고도화

다음 구현은 1차 범위인 플랫폼, 마이페이지, 블로그 상세 개선으로 끊는 것이 가장 깔끔하다.

## 이번 추가사항의 성격

수정된 `추가사항`은 범위가 더 선명해졌다.

특히 블로그 쪽이 `블로그 전체`가 아니라 `상세보기 화면 보정`으로 묶였기 때문에, 이번 구현 범위는 피드나 블로그 메뉴 고도화까지 가지 않고 현재 1차 구현물의 디테일 보정으로 보는 것이 맞다.

현재 요구는 크게 4개다.

- 플랫폼 라벨, 공지 모달, 서비스 카드 문구 보정
- 내 정보 카드 UX와 모달 내부 구조 보정
- 블로그 게시글 상세보기 화면 구조 보정
- 공통 depth 라벨 표기 규칙 적용

즉 신규 라우트나 큰 모델 변경 없이 현재 컴포넌트 수정으로 처리할 수 있다.

## 플랫폼

홈의 `choimory.dev 시작하기`는 `BrandLogo isAnimated={false}`와 ` / welcome` 조합으로 바꾸면 된다.

공지사항 모달은 현재 `max-w-[520px]`라 작은 편이다.

구현 방향:

- 모달 폭을 `max-w-[640px]` 정도로 키운다.
- 라벨은 `notice / post`로 바꾼다.

서비스 카드 우측의 `피드 보기`, `알림 모아보기` 같은 `meta` 문구는 서비스별 의미가 다르므로 일관성이 떨어진다.

구현 방향:

- 활성 서비스는 `이동`으로 통일한다.
- 준비 중 서비스는 `준비 중`을 유지한다.
- 카드 전체 클릭은 그대로 유지한다.

## 내 정보

현재는 서비스 카드와 달리 카드 전체가 클릭되지 않고 우측 버튼만 동작한다.

구현 방향:

- 설정 카드 전체를 클릭 가능하게 변경한다.
- 우측 버튼은 실제 `<button>`이 아니라 `span` 형태의 액션 배지처럼 둔다.
- 이렇게 하면 중첩 클릭 문제를 피할 수 있다.

버튼명은 현재 `수정`, `설정`, `관리`, `탈퇴`가 섞여 있다.

구현 방향:

- 일반 설정은 `열기`로 통일한다.
- 탈퇴만 `확인` 또는 `탈퇴`로 따로 둔다.

개인정보 수정 모달에는 하단 `수정하기` 버튼이 필요하다.

사이트 설정 모달은 현재 테마 radio만 바로 나열되어 있다. 앞으로 설정이 늘어날 예정이므로 `테마 설정` 카드 안에 radio를 넣는 구조가 맞다.

2차 인증은 추가사항대로 사용/미사용을 만들지 않는다.

구현 방향:

- 이메일/모바일 선택만 유지한다.
- 모바일은 disabled와 미구현 표시를 함께 둔다.

## 블로그 상세보기

수정된 메모 기준으로 블로그는 상세보기만 다루면 된다.

현재 순서:

- 본문
- 액션줄
- 좋아요/댓글수

요구 순서:

- 액션줄
- 좋아요/댓글수
- 본문

댓글 입력은 게시글 카드 내부가 아니라 `comments` 영역으로 내려야 한다.

구현 방향:

- 댓글 영역 상단에 댓글 입력창을 둔다.
- 댓글 입력창에는 `작성` 버튼을 추가한다.

구현 방향:

- 답글 달기를 누르면 해당 댓글 아래에 대댓글 입력창을 표시한다.
- 이 작업을 위해 `BlogPostDetailView`는 클라이언트 컴포넌트로 전환한다.

# 추가사항 구현 후 피드백

> 1.공지사항 상세보기 카드가 너무 작아
> 2. 공지사항 상세보기 notice / post 말고 BrandLogo / notice하자 상세보기도
> 3. 2차인증 on/off 얘기한거 안됐어
> 4. 블로그홈같은데 아직 BrandLogo 안쓰고 choimory.dev / blog 이렇게 되어있떤데 이건 2차나 3차구현때 하는건가?

## 공지사항 상세보기 카드 크기

공지사항 상세보기 모달은 폭만 `max-w-[520px]`에서 `max-w-[640px]`로 키웠다.

하지만 실제 체감상 상세보기 카드 자체는 여전히 작게 보일 수 있다.

수정 방향:

- 폭뿐 아니라 내부 여백도 키운다.
- 제목 크기를 조금 키운다.
- 본문 영역을 더 상세 카드처럼 보이게 구성한다.
- 필요하면 본문 영역에 `bg-surface-strong` 같은 내부 패널을 둔다.

즉 단순히 `max-width`만 키우는 것이 아니라, 상세보기 카드의 밀도와 시각적 무게를 함께 조정해야 한다.

## 공지사항 상세보기 라벨

공지사항 상세보기 라벨을 `notice / post`로 바꿨지만, 현재 공통 표기 방향을 생각하면 상세 모달도 `BrandLogo / notice`가 더 일관적이다.

수정 방향:

- 공지사항 목록 상단도 `BrandLogo(애니메이션 없음) / notice`
- 공지사항 상세 모달도 `BrandLogo(애니메이션 없음) / notice`

`notice / post`처럼 내부 depth를 더 나누는 것보다, 현재 단계에서는 공지사항 서비스 영역 안의 상세 모달로 보는 편이 더 자연스럽다.

## 2차 인증 on/off

이전 구현에서는 `2차 인증은 사용/미사용이 없고 이메일/모바일 선택항목만 있음`이라는 메모를 기준으로 해석하여 on/off를 넣지 않았다.

하지만 피드백 기준으로는 `2차 인증 사용 여부` 자체를 켜고 끄는 UI도 필요하다.

수정 방향:

- 2차 인증 사용 여부를 `사용 / 미사용` 형태로 추가한다.
- 인증 방식은 `이메일 / 모바일 앱`으로 둔다.
- 모바일 앱 인증은 아직 미구현 상태이므로 disabled 처리하고 `미구현` 배지를 표시한다.

권장 구조:

- 2차 인증 사용 여부 카드
  - 사용
  - 미사용
- 인증 방식 카드
  - 이메일
  - 모바일 앱 미구현

## BrandLogo depth 표기 적용 범위

이번 구현에서는 현재 만지는 화면 위주로만 `BrandLogo / depth` 표기를 적용했다.

그래서 블로그 홈이나 피드 홈처럼 아직 `choimory.dev / blog`, `choimory.dev / feed` 텍스트를 직접 쓰는 화면이 남아 있다.

공통사항에서 `depth1이 사이트제목일땐 로고(애니메이션x) / depth1`이라고 정했으므로, 결국 이런 텍스트들도 정리 대상이다.

적용 대상 후보:

- `choimory.dev / blog`
- `choimory.dev / feed`
- `choimory.dev / services`
- `choimory.dev / notice`
- `choimory.dev 시작하기`
- 그 외 직접 텍스트로 표기된 `choimory.dev / ...`

수정 방향:

- 눈에 보이는 `choimory.dev / ...` 텍스트는 가능한 한 `BrandLogo size="sm" isAnimated={false} / ...` 구조로 통일한다.
- 단, 상단바의 로고 자체나 큰 메인 로고는 기존 역할이 다르므로 그대로 둔다.

## 피드백 반영 추천 범위

다음 구현에서는 아래 범위를 함께 처리하는 것이 좋다.

1. 공지 상세 모달 크기, 여백, 본문 구조 확대
2. 공지 상세 라벨을 `BrandLogo / notice`로 변경
3. 2차 인증 모달에 `사용 / 미사용` 선택 카드 추가
4. 블로그 홈, 피드 홈 등 눈에 보이는 `choimory.dev / ...` 텍스트를 `BrandLogo / depth`로 통일

이 작업은 신규 라우트나 큰 도메인 모델 변경 없이 UI 표기와 모달 구조 중심으로 처리할 수 있다.
