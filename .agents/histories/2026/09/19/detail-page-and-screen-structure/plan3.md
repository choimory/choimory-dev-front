# 개요

- `plan2.md`에서 2차 구현 범위로 정리한 블로그 메뉴별 상단 특화 카드를 구현한다.
- 현재 블로그 메뉴 화면은 `/blog/popular`, `/blog/following`, `/blog/me` 라우트가 있고, `BlogMenuView`에서 `menuKind`에 따라 제목과 설명만 바꾼 뒤 같은 게시글 목록을 보여준다.
- 2차 구현에서는 메뉴별로 첫 화면에서 기대되는 정보를 상단 카드로 추가한다.

# 2차 구현 범위

## 블로그 인기 화면

`/blog/popular` 상단에는 실시간 검색 순위 또는 인기 키워드 랭킹 카드를 둔다.

구현 내용:

- 인기 글 목록 위에 랭킹 카드를 추가한다.
- 순위 목록을 표시한다.
- 각 순위에는 키워드, 설명 또는 관련 수치, 등락 상태를 표시한다.
- 등락은 작은 badge나 화살표 느낌으로 표현한다.
- 과한 애니메이션보다는 작은 순위 등락 표시가 적합하다.

화면 예시:

- `1 프론트 화면 구조`
- `2 피드 관찰 UX`
- `3 블로그 댓글 개선`

## 블로그 팔로잉 화면

`/blog/following` 상단에는 내가 팔로잉하는 사람 목록과 관리 카드를 둔다.

구현 내용:

- 팔로잉 사용자 목록을 상단 카드로 표시한다.
- 사용자별 닉네임, 짧은 설명, 새 글 여부를 보여준다.
- 관리 진입 버튼을 제공한다.
- 팔로잉 목록은 가로 카드 또는 compact list 형태가 적합하다.

화면 예시:

- `mory.dev`
- `jin.note`
- `ui.archive`

## 내 블로그 화면

`/blog/me` 상단에는 프로필 카드를 둔다.

구현 내용:

- 프로필 이미지 또는 이니셜 영역을 표시한다.
- 닉네임을 표시한다.
- 자기소개를 표시한다.
- 팔로잉 수, 팔로워 수, 작성 글 수를 표시한다.
- 아래에는 기존 글 목록을 유지한다.

타인 블로그까지 생각하면 나중에 `/blog/users/[userId]` 같은 라우트가 필요할 수 있다.

# 구현 방향

## 현재 구조

현재 블로그 메뉴 화면은 다음 구조를 사용한다.

- `src/app/blog/popular/page.tsx`
- `src/app/blog/following/page.tsx`
- `src/app/blog/me/page.tsx`
- `src/features/blog/container/BlogMenuContainer.tsx`
- `src/features/blog/components/BlogMenuView.tsx`
- `src/features/blog/model/blogTypes.ts`

`BlogMenuView`는 `menuKind`를 받아 다음 값에 따라 문구를 바꾼다.

- `popular`
- `following`
- `me`

현재는 메뉴별 제목 카드와 게시글 목록만 렌더링한다.

## 상단 특화 섹션 추가

`BlogMenuView` 내부에서 `menuKind`별 상단 특화 섹션을 추가하는 방식이 자연스럽다.

추천 구조:

- `BlogPopularInsightSection`
- `BlogFollowingManageSection`
- `BlogProfileSummarySection`

단, 처음 구현에서는 파일을 너무 잘게 나누기보다 `BlogMenuView` 내부에서 작은 렌더링 함수 또는 같은 파일 내 보조 컴포넌트로 시작해도 된다.

상단 특화 섹션은 메뉴 제목 카드와 게시글 목록 사이에 배치한다.

배치 순서:

1. 메뉴 제목 카드
2. 메뉴별 상단 특화 카드
3. 게시글 목록

## 타인 블로그 확장 고려

이번 구현은 `/blog/me` 기준 내 블로그 프로필 카드까지만 다룬다.

타인 블로그는 추후 다음 구조를 고려한다.

- `/blog/users/[userId]`
- 사용자 프로필 카드
- 해당 사용자의 글 목록
- 팔로우/언팔로우 액션

이번 2차 구현에서는 라우트를 새로 추가하지 않고, `/blog/me` 화면에서 프로필 카드 구조만 먼저 잡는다.

# 추천 구현 순서

1. `BlogMenuView`에서 `menuKind`별 상단 특화 섹션이 들어갈 위치를 잡는다.
2. 인기 화면 상단 랭킹 카드 mock 데이터를 추가한다.
3. 팔로잉 화면 상단 팔로잉 관리 카드 mock 데이터를 추가한다.
4. 내 블로그 화면 상단 프로필 카드 mock 데이터를 추가한다.
5. 각 상단 카드의 spacing, 카드 밀도, 모바일 폭을 확인한다.
6. `README.md`의 blog 현재 화면 상태에 2차 구현 내용을 반영한다.
7. 타입 검사, lint, build, diff 공백 검사를 수행한다.

# 2차 구현 분석

> 분석시작

## 현재 상태

`plan3`의 2차 구현은 지금 구조와 잘 맞는다.

현재 블로그 메뉴 화면 상태:

- `/blog/popular`, `/blog/following`, `/blog/me` 라우트는 이미 있다.
- `BlogMenuContainer`가 `menuKind`를 받아 `BlogMenuView`로 전달한다.
- `BlogMenuView`는 현재 메뉴 제목 카드, 게시글 목록, 하단 네비게이션을 렌더링한다.
- `BlogMenuKind`는 이미 `popular | following | me`로 정의되어 있다.
- `blogViewModel`에는 `posts`, `tabs`만 있고, 인기 랭킹, 팔로잉, 프로필 데이터는 없다.

핵심은 `BlogMenuView` 하나에서 `menuKind`별로 상단 특화 섹션만 끼워 넣는 작업이다.

## 구현 방식 추천

이번에는 별도 파일을 많이 늘리기보다 `BlogMenuView.tsx` 안에서 보조 컴포넌트 3개를 추가하는 방식이 좋다.

추천 보조 컴포넌트:

- `BlogPopularInsightSection`
- `BlogFollowingManageSection`
- `BlogProfileSummarySection`

이유:

- 전부 mock view data 기반이다.
- 아직 API나 상태 로직이 없다.
- 각 섹션이 `BlogMenuView` 안에서만 쓰인다.
- 나중에 커지면 별도 파일로 분리할 수 있다.

## 데이터 위치

초기 구현은 `BlogMenuView.tsx` 내부 상수로 충분하다.

추천 mock 데이터:

- `POPULAR_KEYWORDS`
  - `rank`
  - `keyword`
  - `description`
  - `changeText`
  - `trend`
- `FOLLOWING_USERS`
  - `id`
  - `nickname`
  - `description`
  - `hasNewPost`
  - `initial`
- `BLOG_PROFILE_SUMMARY`
  - `nickname`
  - `description`
  - `initial`
  - `postCount`
  - `followerCount`
  - `followingCount`

`blogTypes.ts`까지 확장할 수도 있지만, 아직 API 응답 또는 ViewModel 구조로 고정할 단계는 아니다. 따라서 컴포넌트 내부 mock 데이터가 더 가볍다.

## 화면 배치

현재 구조에서 상단 특화 섹션은 메뉴 제목 카드와 게시글 목록 사이에 배치하는 것이 좋다.

배치 순서:

1. 메뉴 제목 카드
2. 메뉴별 상단 특화 섹션
3. 게시글 목록

예시:

```tsx
{menuKind === 'popular' && <BlogPopularInsightSection />}
{menuKind === 'following' && <BlogFollowingManageSection />}
{menuKind === 'me' && <BlogProfileSummarySection />}
```

## 섹션별 디테일

### 인기 화면

인기 화면은 실시간 검색 순위 또는 인기 키워드 랭킹 카드가 적합하다.

구성:

- 카드 제목: `blog / ranking`
- H2: `실시간 검색 순위`
- 3~5개 랭킹
- 등락 badge는 `상승`, `유지`, `신규` 정도로 표시
- 과한 애니메이션은 넣지 않는다.

### 팔로잉 화면

팔로잉 화면은 팔로잉 관리 카드가 적합하다.

구성:

- 카드 제목: `blog / following`
- H2: `팔로잉 관리`
- 내가 팔로잉하는 사용자 compact list
- 새 글 여부 badge
- 관리 버튼은 mock 버튼으로만 표시

### 내 블로그 화면

내 블로그 화면은 프로필 요약 카드가 적합하다.

구성:

- 카드 제목: `blog / profile`
- H2: 닉네임
- 자기소개
- 작성 글 수
- 팔로워 수
- 팔로잉 수
- 프로필 수정 버튼은 mock 버튼으로만 표시

## 주의점

- 카드 안에 카드가 너무 많이 중첩되지 않게 한다.
- 내부 목록은 `bg-surface-strong` 기반의 낮은 대비 리스트가 좋다.
- 현재 프로젝트 규칙상 컴포넌트와 타입에는 Doc Comment가 필요하다.
- 새 컴포넌트를 파일로 나누면 파일마다 Doc Comment를 챙겨야 한다.
- 버튼 동작은 이번 제외 범위이므로 `type="button"`만 둔다.
- README에는 blog 항목에 `인기/팔로잉/내 blog 상단 특화 카드` 정도로만 추가하면 충분하다.

## 구현 범위

이번 2차 구현은 아래까지만 하는 것이 좋다.

1. `BlogMenuView.tsx`에 mock 데이터와 보조 섹션을 추가한다.
2. `menuKind`별 상단 특화 섹션을 렌더링한다.
3. `README.md`의 blog 현재 화면 상태를 갱신한다.
4. 타입 검사, lint, build, diff 공백 검사를 수행한다.

타인 블로그 라우트(`/blog/users/[userId]`)나 실제 팔로잉 관리 모달은 아직 구현하지 않는다.

# 추가사항

- 블로그
  - 인기
    - 랭킹에서 위아래 화살표와 숫자로 얼마나 오르고 내렸는지
    - 랭킹 요소들을 하나씩 촤르륵 펼쳐지는 애니메이션
    - 랭킹 탭을 검색어 / 멘션 / 팔로워 / 태그 4개로 보여줄거임. 검색어는 검색어 입력한거와 순위, 멘션은 멘션 많이된 사용자 (@{nickname}, 화살표 숫자는 멘션횟수), 팔로워는 팔로워 급상승 사용자 (화살표엔 팔로워 상승숫자), 태그는 많이 클릭된 태그 (#{tag}, 화살표는 태그 사용된 숫자)
  - 상세
    - 본문 밑에 태그도 표시 (#{tag}는 필요없고 box?라고하나? `tag` 이런식으로 글자에 살짝 표현되게. 누르면 태그로 검색하게 링크)
  - 팔로잉
    - 인스타 팔로워/팔로잉 목록처럼 간결하게 표시하고, 팔로워(내가 팔로우한)는 목록 옆에 언팔로우 버튼
  - 내 블로그
    - /me로 표시하지말고 그냥 내 nickname으로 표시 (내 블로그라는 별도의 메뉴가 없고 그냥 블로그/닉네임 해서 내 블로그로 이동하는거임)
    - 화면도 그냥 블로그/유저의 메인페이지를 재사용하는식으로 뜨게 할 수 있겠지 그럼
    - 그럼 내 블로그라는 메뉴 소개는 필요가 없고
    - 프로필수정 버튼은 플랫폼의 내 정보에서 하니까 필요없음
    - 팔로워/팔로잉은 누구 팔로워했나, 누가 팔로잉하나 목록 볼수있게 클릭하면 모달창
    - 전반적으로 유저별 블로그 메인 페이지를 더 꾸며야할듯함

# 추가사항 분석

> 분석시작

이번 `plan3` 추가사항은 2차 구현을 실제 SNS 구조에 가깝게 다듬는 내용이다.

## 1차로 바로 보정 가능한 것

현재 구조 안에서 바로 수정 가능한 범위가 있다.

### 인기 랭킹

현재 인기 랭킹은 `상승`, `신규`, `유지` badge만 있다.

요구사항은 위/아래 화살표와 숫자로 얼마나 오르고 내렸는지 표시하는 것이다.

구현 방향:

- mock 데이터에 `changeAmount`를 추가한다.
- `trend`는 `up | down | same | new` 정도로 확장한다.
- 화면에는 `↑ 12`, `↓ 3`, `신규`처럼 표시한다.

### 상세 태그

게시글 상세 화면에는 본문 밑에 태그가 필요하다.

구현 방향:

- `BlogPost` 모델에 `tags: string[]`를 추가한다.
- 상세 화면 본문 아래에 태그 badge link를 표시한다.
- `#{tag}` 텍스트보다는 작은 box/badge 형태로 표현한다.
- 링크는 일단 `/blog?tag=...` 또는 `/blog/popular?tag=...` 같은 mock 링크로 둔다.

### 팔로잉 목록

현재 팔로잉 화면은 설명과 새 글 badge 중심이다.

요구사항은 인스타 팔로워/팔로잉 목록처럼 간결한 목록과 언팔로우 버튼이다.

구현 방향:

- compact list 형태로 바꾼다.
- 목록 오른쪽에 `언팔로우` 버튼을 둔다.
- 실제 동작은 제외하고 버튼만 표시한다.

## 2차로 구조 전환이 필요한 것

내 블로그 쪽은 단순 UI 보정보다 라우팅 개념이 바뀐다.

현재 구조:

- `/blog/me`
- 하단 탭 라벨 `내 블로그`
- 화면 라벨 `blog / me`
- 프로필 수정 버튼 있음

요구 방향:

- `내 블로그`라는 별도 메뉴 소개는 없다.
- 내 블로그도 유저별 블로그 메인 페이지의 한 케이스다.
- `/me`가 아니라 닉네임 기반으로 표시한다.
- 라우트도 결국 `/blog/users/[userId]` 또는 `/blog/@[nickname]` 계열이 자연스럽다.
- 프로필 수정 버튼은 플랫폼의 내 정보에서 하므로 제거한다.
- 팔로워/팔로잉 수 클릭 시 목록 모달을 표시한다.

추천 방향:

- 이번 단계에서는 라우트를 바로 갈아엎기보다 UI를 먼저 유저 블로그 메인 페이지처럼 바꾼다.
- `/blog/me`는 당장 유지한다.
- 화면 라벨은 `blog / mory.dev`처럼 닉네임 기반으로 바꾼다.
- 제목은 `mory.dev`로 둔다.
- `내 블로그` 설명 카드는 제거하거나 약화한다.
- 프로필 수정 버튼은 제거한다.
- 팔로워/팔로잉 지표는 버튼화한다.
- 클릭 시 팔로워/팔로잉 목록 모달을 표시한다.

그 다음 단계에서 라우트를 `/blog/users/[userId]`로 확장하는 것이 안전하다.

## 인기 랭킹 탭 4개

인기 랭킹은 4개 탭이 필요하다.

- 검색어
- 멘션
- 팔로워
- 태그

각 탭의 의미:

- 검색어: 검색어 입력어와 순위
- 멘션: 많이 멘션된 사용자 `@{nickname}`, 화살표 숫자는 멘션 횟수
- 팔로워: 팔로워 급상승 사용자, 화살표 숫자는 팔로워 상승 수
- 태그: 많이 클릭된 태그 `#{tag}`, 화살표 숫자는 태그 사용 수

탭을 클릭해서 목록을 바꾸려면 상태가 필요하다.

선택지:

- `BlogMenuView` 전체를 클라이언트 컴포넌트로 전환한다.
- `BlogPopularInsightSection`만 별도 클라이언트 컴포넌트로 분리한다.

추천:

- 구조상 랭킹 탭만 상태가 필요하므로 `BlogPopularInsightSection`을 별도 클라이언트 컴포넌트로 분리하는 것이 가장 깔끔하다.
- 다만 구현량을 줄이려면 `BlogMenuView`에 `useState`를 추가하는 방식도 가능하다.

## 애니메이션

랭킹 요소들이 하나씩 펼쳐지는 애니메이션은 CSS animation으로 충분하다.

구현 방향:

- 랭킹 item에 `style={{ animationDelay: `${index * 60}ms` }}`를 줄 수 있다.
- CSS class는 예를 들어 `blog-ranking-enter`처럼 둘 수 있다.
- `globals.css`에 keyframes를 추가해야 한다.

주의:

- 새 CSS를 넣으면 전역 CSS 변경이 들어간다.
- 과하게 하지 않고, 작은 stagger 느낌만 주는 것이 적당하다.

## 바로 보정 가능한 범위

- 인기 랭킹을 3개에서 5개로 늘리는 것은 mock 데이터만 추가하면 된다.
- 팔로잉 화면을 `팔로워 / 팔로잉` 탭으로 나누는 것도 현재 `BlogMenuView`가 client component라 바로 가능하다.
- 팔로잉/팔로워 검색 버튼은 우선 아이콘 버튼 또는 검색 입력 토글 형태로 넣을 수 있다.
- 화살표 paging은 mock 데이터 기준으로 이전/다음 버튼과 현재 page index 상태를 두면 된다.
- 내 블로그 화면에서 소개 카드 제거, 프로필 카드 위 라벨 이동, 글 목록 위 `blog / post - 포스트` 라벨 추가도 바로 가능하다.

## 구조 전환이 필요한 범위

핵심은 `/blog/me`를 없애고, 내 블로그도 유저 블로그 페이지로 통합하는 부분이다.

추천 라우트:

- `/blog/users/[nickname]`

이유:

- Next 라우팅에서 안정적이다.
- 나중에 타인 블로그로 확장하기 쉽다.
- `mory.dev` 같은 닉네임을 path segment로 그대로 바인딩할 수 있다.

하단 네비게이션은 다음처럼 정리하는 것이 좋다.

- label: `내 블로그`
- href: `/blog/users/mory.dev`

즉, 툴바나 하단 메뉴의 워딩을 없애는 것이 아니라, 이동 대상 화면을 유저 블로그 메인 페이지로 바꾸는 것이다.

`/blog/me`는 제거 대상이지만, 기존 링크 깨짐을 막으려면 구현 과정에서는 redirect 또는 임시 호환 페이지를 둘 수 있다.

## 유저 블로그 메인 화면 방향

2. `blog / @{nickname}` 라벨
3. 프로필 카드
4. `blog / post - 포스트` 라벨
5. 해당 유저의 글 목록
6. 하단 네비게이션
