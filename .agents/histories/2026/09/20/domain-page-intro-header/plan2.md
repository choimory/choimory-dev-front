# px-1 헤더 패턴 전수 조사

`src/features/`, `src/shared/` 전체에서 헤더용 `px-1` wrapper를 조사한 결과, 총 18곳에서 5가지 패턴으로 갈라져 있음을 확인함.

| 그룹 | 구조 | 개수 | 예시 |
|---|---|---|---|
| A | eyebrow만 (`<section>`) | 3 | `blog / me`, `feed / me`, `blog / @{nickname}` |
| B | eyebrow + h2 (`<div>`) | 12 (최다) | `blog / setting` + "설정" |
| C | eyebrow + h1 (`<section>`) | 1 | `blog / post` + "포스트" (게시글 상세 최상단) |
| D | 로고 + eyebrow + h1 + description | 1 | `PageIntroCard` (공용 컴포넌트) |
| E | eyebrow + h2 + 우측 액션링크(flex 변형) | 1 | "공개 글 미리보기" + "지금 둘러볼 수 있는 글" + "참여하기" 링크 |

## 그룹별 상세

- **A (eyebrow만)**: `BlogMeSettingsView.tsx`(`blog / me`), `BlogUserBlogView.tsx`(`blog / @{nickname}`), `FeedMenuView.tsx`(`feed / me`). h1/h2 없이 eyebrow만 있고, 뒤따르는 프로필 카드가 실질적 헤딩 역할을 함.
- **B (eyebrow + h2, 가장 흔함)**: `MemberServiceFeedSection.tsx` 2곳, `BlogMeSettingsView.tsx`(`blog / setting`), `BlogUserBlogView.tsx`(`blog / post`), `BlogPostDetailView.tsx`(`blog / comments`), `FeedView.tsx` 4곳, `FeedMenuView.tsx` 3곳(`feed / event`, `feed / target`, `feed / settings`).
- **C (eyebrow + h1)**: `BlogPostDetailView.tsx` 최상단(`blog / post` + "포스트"). 페이지 최상단인데 로고가 없어 D와도, 서브헤더인 B와도 다른 애매한 위치.
- **D (`PageIntroCard`)**: 로고 포함, 페이지 최상단 전용. `domainPath`/`title`/`description` prop.
- **E (변형)**: `BlogGuestSection.tsx`. B와 텍스트 구조는 같지만 `flex items-end justify-between` + 우측 "참여하기" 링크가 추가됨.

# 규격화 제안 및 확인 필요 사항

## 제안 방향

`PageIntroCard`(D)는 로고가 들어간 페이지 최상단 전용이라 이미 목적이 분명함. 문제는 B/C/E처럼 로고 없는 섹션 서브헤더가 구조가 제각각이라는 점. 가장 흔한 B 패턴(eyebrow+h2)을 기준으로 공용 컴포넌트(가칭 `SectionHeader`)로 묶고, A(eyebrow만)는 타이틀/description을 생략 가능하게, E(우측 액션링크)는 선택적 `action` prop으로 흡수하는 방향을 제안함.

## 확인 필요 사항

1. **범위**: 이번에 규격화할 대상이 B/C/E처럼 로고 없는 섹션 서브헤더들인지, 아니면 `PageIntroCard`(D)까지 포함해서 전체를 하나의 유연한 컴포넌트로 합칠지.
2. **C그룹 처리**: `BlogPostDetailView`의 최상단 h1(`blog / post` + "포스트")은 페이지 최상단인데 로고가 없어 D와도 다르고 B와도 다른데, 이것도 이번 정리 대상에 포함할지.
3. **320px 줄바꿈 적용 범위**: 로고+"/ 도메인"(D, `PageIntroCard`)에서 로고 줄바꿈 후 "/depth1/depth2"를 아래 줄에 두는 처리를 말씀하신 것인지. B~E처럼 로고 없는 eyebrow(`blog / setting` 같은 텍스트)도 같은 처리가 필요한지, 아니면 로고가 들어간 D만 해당인지.

# 문구 톤앤매너와 컴포넌트 축소 방향

> 일단 문구부터가 다 제각각이라 톤앤매너를 맞춰야할거 같고,
> 헤더는 모두 다 사용 > 섹션나누기용도는 두개만 사용 뭐 이런식으로 조금씩 줄이면서 조정하면 될거 같은데

## 답변

문구 톤 확인 결과, eyebrow 텍스트가 두 스타일로 나뉘어 있었음.

- `blog / me`, `feed / event`, `blog / setting` 같은 "서비스 / 도메인" 영문 슬래시 포맷 (대부분)
- `관찰 중인 대상`, `최근 이벤트`, `공개 글 미리보기` 같은 자유 한글 문구 (`FeedView.tsx` 4곳, `BlogGuestSection.tsx` 1곳)
- `MemberServiceFeedSection.tsx`는 `/me`, `/services`처럼 서비스명 없이 depth만 있어 애매함

컴포넌트 축소 방향은 5개 패턴을 용도별 2개로 정리하는 것으로 제안함.

- **① 페이지 최상단용(로고 포함)**: `PageIntroCard`를 확장해서 title/description을 선택 prop으로 만들고, 도메인 목록 페이지 6곳뿐 아니라 A그룹(`blog / me`, `feed / me`, `blog / @{nickname}`), C그룹(게시글 상세 최상단)까지 커버
- **② 섹션구분용(로고 없음)**: 새 컴포넌트(가칭 `SectionHeader`)로 B그룹(eyebrow+h2) 12곳과 E그룹(우측 액션링크 변형) 1곳을 통일

# heading 톤 확인

> 내가 말한 문구는 blog / me 이쪽 말고 그 밑에 한글로 적힌 heading 부분임. 어느부분은 "공지사항"으로 끝인데 어느부분은 "사용하실 서비스를 선택하세요" 이런식의 따듯한 문구고

## 답변

`PageIntroCard` 6곳의 타이틀/설명을 정리하면 아래와 같이 톤이 갈려 있었음.

| 페이지 | 타이틀 | 설명 |
|---|---|---|
| 공지사항 | "공지사항" | 플랫폼과 하위 서비스의 변경사항을 모아봅니다. |
| 서비스 | "사용할 서비스를 선택하세요" | 현재 열린 서비스와 준비 중인 서비스를 한 화면에서 확인합니다. |
| 블로그 인기 | "지금 인기 있는 글" | 검색어, 멘션, 팔로워, 태그 흐름을 기준으로 많이 움직이는 글을 모아봅니다. |
| 블로그 팔로잉 | "팔로잉 피드" | 팔로워와 팔로잉 목록을 확인하고 필요한 사용자를 빠르게 찾습니다. |
| 피드 인기 | "인기 관찰 대상 랭킹" | 등록과 반응이 늘고 있는 아이템, 스트리머, 아티스트를 모아봅니다. |
| 피드 관찰 | "관찰 목록" | 가격, 방송, 신곡처럼 계속 지켜볼 대상을 확인합니다. |

"공지사항"/"팔로잉 피드"/"관찰 목록"/"인기 관찰 대상 랭킹"은 명사형으로 짧게 끝나는데, "사용할 서비스를 선택하세요"만 말 걸듯한 문장형이고 "지금 인기 있는 글"도 그 중간쯤이라 톤이 갈림을 확인함.

질문: "타이틀 톤을 어느 쪽으로 통일할까요?" (명사형 짧게 / 따뜻한 문장형) → 답변: "명사형 짧게 (추천)"

# 최종 규칙 정리

> 일단 정리하자 
>
> eyebrow = 페이지 맨 위의 헤더 (페이지소개)는 로고/서비스/도메인, 페이지 중간중간 쓰이는 섹션 구분은 로고 없이 서비스/도메인
>
> heading = 간결하게 
>
> heading 밑의 description = 페이지 맨 위의 헤더에서만 사용. 따뜻한 안내형 문구. 페이지 내 섹션 구분용 나머지들은 eyebrow랑 heading정도만.

## 답변

질문: "프로필 카드 바로 위에 있는 eyebrow(지금의 `blog / me`, `feed / me`, `blog / @{닉네임}`)는 어느 카테고리로 볼까요?" (페이지소개로 승격 / 섹션구분으로 유지) → 답변: "페이지소개(로고 포함)로 승격 (추천)" — 프로필카드도 페이지 최상단이므로 로고를 추가하되, heading/description은 프로필카드의 닉네임/자기소개가 대신하므로 생략 유지.

# 최종 정리 및 컴포넌트 매핑

## 규칙

- **eyebrow**
  - 페이지소개(페이지 최상단, 도메인 목록 페이지 + 프로필형 페이지 모두 포함): `{로고} / {서비스} / {도메인}`
  - 섹션구분(페이지 중간): `{서비스} / {도메인}` — 로고 없음
- **heading**: 전부 간결한 명사형으로 통일
- **description**: 페이지소개 헤더에서만 사용(그것도 선택적 — 도메인 목록 페이지는 있고, 프로필형 페이지는 프로필 카드가 대신하니 생략), 따뜻한 안내형 문구. 섹션구분용은 description 없음.

## 컴포넌트 매핑

- **`PageIntroCard`(페이지 최상단, 로고 포함)**: title/description을 선택 prop으로 확장해서 아래 10곳을 커버
  - 도메인 목록 페이지 6곳(공지사항/서비스/블로그 인기·팔로잉/피드 인기·관찰) — title+description 모두 사용
  - 프로필형 페이지 4곳(`blog / me`, `feed / me`, `blog / @{nickname}`, 게시글 상세 최상단) — eyebrow(+필요 시 간결한 heading)만 사용, description은 생략
- **`SectionHeader`(가칭, 섹션구분, 로고 없음)**: 아래 13곳을 커버, eyebrow+heading만 사용
  - B그룹 12곳(eyebrow+h2)
  - E그룹 1곳(우측 액션링크 변형) — "참여하기" 같은 액션은 선택적 슬롯으로 흡수

## 남은 확인 사항

- heading 톤 정리(예: "사용할 서비스를 선택하세요" → "서비스", "지금 인기 있는 글" → "인기 글") 문구를 내가 초안을 잡아서 보여줄지, 직접 다 정해줄지 미확인.
- 320px 줄바꿈 처리(로고 줄바꿈 후 "/depth1/depth2"를 아래 줄) 적용 범위(`PageIntroCard`만인지, `SectionHeader`도인지) 미확인.

# 문구 톤 범위 및 게시글 제목 확인

> 1. 웬만하면 사이트 전체
> 2. title 추가

## 답변

### 1. 사이트 전체 톤 변경 범위 조사

`~합니다`/`~입니다`로 끝나는 텍스트를 코드 주석(JSDoc) 제외하고 전수 조사한 결과, 17개 파일에서 50곳 확인함. 성격이 섞여 있어 그대로 일괄 변경하면 어색해지는 부분이 있어 3가지로 분류함.

- **(a) 안내/설명 문구**: `PageIntroCard`/`SectionHeader`의 description, 설정 항목 설명(`MeSettingItem`, `BlogSettingItem`), feed 소개(`signals`, `guestBenefits`), 서비스/계정 소개 문구 등. → "~하세요/~해보세요" 권유형으로 변경.
- **(b) 시스템 알림/이벤트 로그**: `recentAlerts`(예: "새 싱글 티저가 공개되었습니다."), 알림 제목(예: "서비스 데이터 구조를 준비 중입니다"), 활동 피드 항목 등. 권유가 아니라 이미 일어난 일을 통보하는 텍스트라 → "~했어요/~됐어요" 완료형으로 변경.
- **(c) 댓글/대화 내용**: `BlogPostDetailView`의 mock 댓글(예: "이 구조면 상세 화면을 붙이기 쉬워 보입니다.")은 가상의 다른 유저가 남긴 말이라 사이트 톤 규칙 적용 대상에서 제외.

### 2. 게시글 title 필드 추가 계획

`BlogPost` 타입에 `title: string` 필드를 추가하고, `blogViewModel`의 mock 게시글 2개(`post-1`, `post-2`)에 제목을 채운 뒤 `BlogPostCard`(목록)와 `BlogPostDetailView`(상세 페이지 `PageIntroCard` 타이틀, 기존 `포스트` 대체)에 반영하기로 함.

질문: "(a)=권유형, (b)=완료형, (c)=제외로 나눠서 진행해도 될까요? title 필드 추가 계획대로 진행하면 될까요?" → 답변: "응 그렇게 진행해줘"
